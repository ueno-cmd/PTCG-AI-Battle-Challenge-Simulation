## 1. なぜこの修正をしたか

ver24・ver25 の40戦（19勝21敗、47.5%）を3体のサブエージェントで並行解析した結果、
**最大の失点源は相手の火力ではなく「バトル場にエネルギーが乗らないこと」**だと判明した。

| | 負け21戦 | 勝ち19戦 |
|---|---|---|
| 自分のターンでバトル場のエネが2個未満（＝メガブレイブを撃てない） | **94.2%** (129/137) | 68.5% |
| バトル場のエネが0個 | 75.2% | 42.3% |
| 攻撃を実行できたターン | 43.1% | 64.3% |
| 1試合の平均与ダメージ | **331** | 903 |

`superpowers:systematic-debugging` で原因を追跡し、実データでの再現まで確認した。

**なお、2026-07-28 に入れた3修正（Belt温存・Riolu供給・進化優先度）はすべて狙いどおり効いていた**
（Belt自己トラッシュ 4件→0件、Belt装着率 38%→65%、サーチでのRiolu非選択（旧ロジック起因）11件→0件）。
それでも勝率が45%→47.5%とほぼ動かなかったことから、**これらは勝敗を決める要因ではなかった**と判断できた。
プロセス指標で測っていたからこそ「修正は成功したが的が外れていた」と切り分けられた
（勝率だけを見ていたら「修正が失敗した」と誤診していた）。

## 2. 原因1：ハイパーボール等のコストで闘エネルギーを優先的に捨てていた

### 症状と再現

`src/lucario_agent/main.py` の `_score_card_option`、`SelectContext.DISCARD` 分岐が
**手札に基本闘エネルギーが2枚以上あるとスコア +50 を返していた**。これは汎用トレーナーズの
既定値 10 より高いため、エネルギーが真っ先に捨てられていた。

実測（ログ `88607286` step18、ハイパーボールのコスト2枚選択）:

| 手札の候補 | スコア | 結果 |
|---|---|---|
| 基本闘エネルギー | 50 | **捨てられた** |
| 基本闘エネルギー | 50 | **捨てられた** |
| Pokégear 3.0 | 10 | 残った |
| Judge | -100 | 残った |
| Judge | -100 | 残った |

この試合はT1でエネルギー2枚を失い、その後12ターンにわたりバトル場のオーガポンexが0エネで棒立ちになった。
デッキ内のエネルギーは11枚しかない。

「守っている」つもりの `-20` も不十分で、Boss's Orders / Lillie's Determination（-50）や
Judge（-100）より高いため、それらが代替候補のときは手札に1枚しかなくてもエネルギーが捨てられていた
（`88591718` step11）。ロック闘エネルギー（-20、デッキ4枚・夜のタンカで回収不可）も同様
（`88591718` step19）。

**40戦で、他に捨てられる札があったのにエネルギーを選んだケースが16件（計23枚）。**

### 修正内容（コミット `d32fda2`）

DISCARD のスコア序列を組み替えた。値はすべて相異なり、同点は無い。

| カード | 変更前 | 変更後 |
|---|---|---|
| 汎用トレーナーズ | 10 | 10（据置） |
| Boss's Orders / Lillie's Determination | -50 | -50（据置） |
| **基本闘エネルギー（手札3枚以上）** | 50 | **-60** |
| **基本闘エネルギー（手札2枚以下）** | 50 / -20 | **-90** |
| **ロック闘エネルギー** | -20 | **-95** |
| キーポケモン / Judge | -100 | -100（据置） |
| Maximum Belt | -150 | -150（据置） |

**重要な設計判断：エネルギーをキーポケモン（-100）より下げてはいけない。**
下げると、コスト候補が全部高価値なとき（例：手札が [リオル, 基本闘, 基本闘]）にリオルを捨ててしまう。
ハイパーボールはポケモンをサーチするカードなので、ポケモンを捨ててポケモンを取るのは本末転倒になる。
これは `test_energy_still_discarded_before_key_pokemon` でガードレール化した。

ルナサイクル（ルナトーンの特性）のコスト支払いには影響しない。選択肢が基本闘エネルギーのみであり、
`return desc_indices[:select.maxCount]` はスコアの正負に関わらず上位 maxCount 件を返すため。
加えて発動条件自体が `hand_counts[Basic_Fighting_Energy] >= 2` でガードされている（最終レビューで裏取り済み）。

## 3. 原因2：バトル場が0エネでも10点差でベンチに装着していた

### 症状と再現

`energy_score`（`combat.py`）のバトル場ボーナスは `+10` のみで、ベンチのリオル／メガルカリオexが
受け取る `+100`（エネルギー2個未満）に押し負けていた。実盤面での再現値：

| 装着先 | スコア |
|---|---|
| バトル場のオーガポンex / 0エネ | **8090** |
| ベンチのリオル / 0エネ | **8100** ← 実際に選ばれた |
| ベンチのメガルカリオex / 1エネ | 8101 |

**40戦で30件**、バトル場が0エネなのにベンチへ装着していた（30件すべてでバトル場に付ける選択肢も提示されていた）。

**構造的な核心：バトル場が0エネだと「技を撃てない」だけでなく「にげるコストを払えない」ため、
自力では絶対に場を離れられないデッドロックになる。** エネルギーは上記のスコア差でベンチへ流れ続けるため、
バトル場は永久に死んだままになる。

裏付けとなる実測（40戦）:

| バトル場にいたポケモン | 延べターン数 | うちエネ0 | 実際の攻撃回数 |
|---|---|---|---|
| **オーガポンex** | **95（最多）** | **73%** | **18回** |
| メガルカリオex | 92 | 21% | 109回 |
| ソルロック | 30 | 73% | 21回 |
| ルナトーン | 37 | 89% | — |

### 修正内容（コミット `ad4d2f3`、`0540703` で値を調整）

`_score_attach_option` のバトル場分岐に救済ボーナスを追加した。`combat.py` の `energy_score` は
変更していない（救済判断には攻撃プラン `current_plan` が必要だが `energy_score` はそれを受け取らないため）。

```python
if o.inPlayArea == AreaType.ACTIVE:
    if current_plan.attacker == 0 and current_plan.energy:
        score += 200
    elif not current_plan.energy and not pokemon.energies:
        score += 300   # バトル場0エネのデッドロック救済
```

`AttackPlan.energy` は「今ターン攻撃するために、あと1個エネルギーを装着する必要がある」を表す
（`combat.py` の `more_energy = True`）。したがって `current_plan.energy == False` は
「追加装着で今ターン攻撃できるプランが無い」を意味し、**成立している攻撃プランを横取りしない**。

## 4. 最終レビューで発見された計画の欠陥（重要）

**当初 +500 としていたが、最終レビュー（Opus）で計画のタイ分析が誤っていたことが判明した。**

救済ボーナスは、同じ関数内にある **Rock_Fighting_Energy のアクティブ優先 +500 と排他ではなく加算される**。
計画書の「素の `energy_score`（7900〜8101）とだけ競合する」という前提は誤りで、実際の ATTACH 最大値は

```
バトル場 オーガポンex 0エネ + ロック闘エネ + attacker1
= 8000 +10 +80 +40 +500(ロック) +500(救済) = 9130
```

に達していた。これは 2026-07-28 に自ら立てた不変条件
**「9000〜10000の間に他のスコアは存在しない」**（EVOLVE を Judge との同点事故から守るためのもの）を破っていた。
EVOLVE は `9100 + エネ数` なので、ATTACH が EVOLVE を追い越す順序逆転が起きていた。

**同点（完全一致）自体は総当たり検証で0件、実害もゼロ**（MAIN は1ターンに複数回行動できるため
装着→進化で両立する）だったが、コードに「破られていない」と書いてあるまま帯域が侵食されている状態は、
次にこの帯域へ加点した人が事故る温床である。

**ユーザー判断により +500 → +300 に変更**（コミット `0540703`）。最大値が **8930** となり 9000 未満に収まった。
副次的に、救済が ABILITY のルナサイクル（8500）を追い越して「引いてから付ける」順序が
「付けてから引く」に反転していた退行も解消された（8390 < 8500）。

+300 の根拠：
- **下限** — ベンチのメガルカリオex 1エネ（8101）に確実に勝つ必要がある（バトル場ルナトーン0エネ = 8210 > 8101）
- **上限** — ロック闘エネの +500 と重なっても 9000 を超えないこと（最大 8930）

この加算関係は `test_rock_fighting_energy_rescue_stacks_with_active_priority_and_stays_below_evolve`
で回帰テスト化し、「加算されること」と「9000未満に収まること」の両方を固定した。

### 総当たり検証で発見された既存の同点（今回の変更とは無関係・未修正）

- `score = -1` — コードベース全体で12箇所以上が返す汎用センチネル値。互いに衝突するが設計上の意図
- **`score = 7000` — Judge（PLAY）と リオルへの Air Balloon（ATTACH）が一致する。**
  Air Balloon 分岐は救済ボーナスに到達する前に return するため今回の変更とは無関係だが、
  **センチネルでない実スコア同士の同点であり、選択肢の提示順で結果が決まる潜在的な問題**。
  スコープ外として未修正。次回以降の検討事項

## 8. 本作業で扱わなかったこと（次回以降の判断材料）

1. **原因3：オーガポンexのデッドロック** — 技「ぶちやぶる」は闘エネ3個、にげるコストは1。
   0エネだと攻撃も退却もできない。40戦でバトル場に95ターン居座り、うち73%が0エネ、攻撃は18回のみ。
   **本修正で緩和されるかを実測してから対処を判断する**（ユーザーの明示的な決定）
2. **デッキ構成変更（オーガポンex → マクノシタ2／ハリテヤマ2）** — ハリテヤマの「ワイルドプレス」も
   闘エネ3個要求・にげるコスト3なので、**エネルギー事故の解決にはならない**。ただし特性
   「どすこいキャッチャー」（手札から出して進化させたとき、相手のベンチポケモンをバトル場に引きずり出す）は
   テンポ面で価値が高い
3. **`UltraBallPolicy` 側でのコスト回避** — 順位付けによる温存では、選択肢が高価値な札しかない場合に
   「捨てない」を選べない。恒久対策は「コスト候補が全部高価値ならハイパーボール自体を撃たない」判定
4. **`score = 7000` の既存の同点**（Judge と リオルへの Air Balloon）
5. **計測スクリプトの `avoidable` 判定** — 部分的に回避できたケース（minCount=2 で代替候補1枚）を
   取りこぼす。前後比較の基準を変えないため今回は据え置き
