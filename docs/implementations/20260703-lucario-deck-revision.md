**関連計画書：** `docs/superpowers/plans/2026-07-03-lucario-deck-revision.md`

## 1. 背景

Kaggleコンペ提出用ルカリオexデッキのLBスコアが523〜676で乱高下していた。バトルログ8件
（83465939, 83484940, 83509359, 83509516, 83510250, 83534688, 83563077, 83574179）を解析した結果、
4勝4敗で、敗因は以下の2系統に整理できた。

1. **デッキアウト負け（2敗：83465939, 83484940）**：賞金レースで有利、または互角にもかかわらず
   自分の山札が0枚になり敗北。「カーマイン」（手札を捨てて5枚ドロー、1試合で6回使用）や
   「リーリエの決心」（手札を山札に戻して6〜8枚ドロー）を、山札残数を考慮せず無条件で高スコアに
   する旧`_score_play_option`の設計が主因。
2. **速攻・高火力デッキへの対応不足（2敗：83534688, 83574179）**
   - 83534688（対グリムスナールex系）：リオル3枚中2枚が自分のプライズに埋まる事故により、
     メガルカリオexが一度も攻撃せず盤面全滅。
   - 83574179（対アラカザム）：唯一のメインアタッカーだったメガルカリオex（3賞金分）を一撃で
     失い敗北。ベンチには温存されたエネルギー3個のハリテヤマがいたが未使用のまま終戦。

なお、メガルカリオex自体は勝ち試合ではターン3〜4で立ち上がっており、デッキ設計自体は正しく
アグロとして機能している。問題は「デッキアウトを誘発する無条件ドロー」と「事故時のリカバリー
手段の薄さ」だった。

この分析を踏まえ、2026-07-02大会優勝デッキをベースにした軽量プラン（マクノシタ・ハリテヤマ系統
を撤去し、リオル/メガルカリオex/ソルロック/ルナトーンの4本柱に絞る構成）を採用し、あわせて
エージェントロジックを`src/grimmsnarl_agent/main.py`と同じルールベース＋コンテキストバンディット
（ε-greedy）のハイブリッドに刷新した。

### 2.1 デッキ構成（`decks/lucario_20260621.py`）

リオル4・メガルカリオex3・ソルロック4・ルナトーン2の4本柱に、ファイトゴング・ハイパーボール・
ポケパッド・パワープロテイン・夜のタンカ・ポケギア3.0・ヒーローマント（ACE SPEC 1枚）・
リーリエの決心・ボスの指令・ジャッジマン・トウコ・ミツルの思いやり・暗号マニアの解読・
グラビティーマウンテン・基本闘エネルギー11枚を加えた合計60枚に全面差し替えた。マクノシタ・
ハリテヤマ・Dusk Ball・Carmine・Switchは撤去。

### 2.2 不要ロジックの削除

`energy_score()`・`_collect_field_state()`・`calc_attack_plan()`・`_score_card_option()`・
`_score_play_option()`・`_score_attach_option()`・`_score_option()`からマクノシタ・ハリテヤマ
専用の分岐（`attacker2`概念含む）とCarmine・Switch分岐を削除し、シグネチャを整理した。

### 2.3 デッキアウト防止ゲート

`DECK_SAFETY_THRESHOLD = 15`を新設し、山札残数がこれ未満なら大量ドロー系（リーリエの決心・
ルナサイクル）を`-1`に抑制する共通ロジックを適用した。

### 2.4 ルナサイクル（ルナトーンの特性）

ソルロックが場におり手札に基本闘エネルギーがある場合に高スコアを返す判定と、
`SelectContext.DISCARD`（闘エネルギーを優先して捨てる／重要ポケモン・サポーターを保護する）を
新規実装した。発動判定はデッキアウトゲートの対象。

### 2.5 新規カードのスコアリング

ハイパーボール・ポケギア3.0・夜のタンカ・ジャッジマン（手札事故時のみ使用）・トウコ・
ミツルの思いやり（メガルカリオexが減っている時のみ使用）・暗号マニアの解読の7枚に
`_score_play_option()`内でスコアリングを追加した。

### 2.6 ボスの指令・メガブレイブのε-greedy化

`src/grimmsnarl_agent/main.py`と同じパターン（`EPSILON = 0.28`、`_rng = random.Random()`、
テストでは`rng`引数にスタブを注入可能）を移植した。

- **ボスの指令**：対象不在なら温存（-1）、確定KOなら即使用（8800）、それ以外は
  `rng.random() < EPSILON`なら探索的先出し（6000）、外れなら温存（-1）。
- **メガブレイブ**（本タスクで実装）：通常攻撃(130ダメ)で確定KOが取れるならメガブレイブは
  温存（スコア-1000のペナルティでクールダウンを節約）。メガブレイブでしか取れない確定KOが
  あれば即使用。どちらでも確定KOが取れない場合は`active_rng.random() >= EPSILON`ならスコア
  -300（温存寄り）、`< EPSILON`なら無ペナルティ（探索的に先出しして圧をかける）。旧来の
  「`a == 1 and my_prize in (2, 3)`ならペナルティ」という固定ヒューリスティックは、この新
  ロジックに完全に置き換えて削除した。

`calc_attack_plan()`のシグネチャに`rng: "random.Random | None" = None`を追加し、本番では
`agent()`からの呼び出し（引数変更なし）で自動的にモジュールレベルの`_rng`にフォールバックする。

## 4. 未対応・次回持ち越し事項

- `DECK_SAFETY_THRESHOLD = 15`は仮置きの値。次回以降の実戦バトルログで有効性を確認し調整する。
- ミツルの思いやり（対象が複数ある場合の選択）・暗号マニアの解読（山札上2枚の並び替え）の
  詳細なfollow-up選択ロジックは、実際にどの`SelectContext`が発火するか確認できていないため、
  汎用スコアリング（デフォルト0点でのタイブレーク）に委ねている。実戦ログで挙動確認後に
  専用ロジックを追加するか判断する。
- 83574179（対アラカザム）で見られた「リオル展開がターン8までかかった」現象の根本原因は
  未解明のまま。今回のハイパーボール導入（Dusk Ballより探索精度が高い）で改善するかは、
  次回のバトルログで検証する。
- メガブレイブのε-greedy判定における`EPSILON = 0.28`はボスの指令と共通の値を流用しており、
  メガブレイブ固有に最適化した値ではない。実戦での探索/温存バランスを見て個別調整の要否を
  次回検討する。
