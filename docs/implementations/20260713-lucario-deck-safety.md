## 背景

ユーザーが手動DLしたルカリオの直近バトルログ12件（85600090〜85666055、`Kagura_UT`視点）を解析した結果、2勝10敗だった。うち9敗はプライズ先取レースで押し切られた通常の負け（対策は本作業のスコープ外）だったが、**85626724（対メガガルーラex×4）だけは明確な構造上のバグによる負け**と判明した：32ターンの長期戦で、自分がプライズ3枚先取（相手は1枚）と有利だったにもかかわらず、山札が0枚になりデッキアウトで敗北していた。

原因は、`lucario_agent`の山札対策`DECK_SAFETY_THRESHOLD = 15`が「ミツルの思いやり」と「ルナサイクル」（Lunatoneの特性）の2つしかゲートしておらず、ヒルダ・ポケギア3.0・ハイパーボール・暗号マニアの解読・ジャッジマンなど他のドロー/サーチ系カードが山札残数を一切見ずに使用され続けていたこと。実際にT17で山札残9枚の状態でポケギア3.0を使うなど終盤も歯止めがかからなかった。

これは2026-07-02〜07-12にグリムスナールexで発見・修正済みの「山札セーフティ」バグと同じ種類の穴であり、実戦検証済みの修正パターン（`_safe_draws`＝山札残数−残りプライズ数−1で全ドロー系カードを一括ゲート）をそのまま移植した。

## 変更内容

- `_safe_draws(my_state) -> int`と`_deck_consumption(card_id, my_state, hand_counts) -> int | None`を新設（`_score_play_option`の直前）
- `_score_play_option()`冒頭にガード節を追加し、ミツルの思いやり・ジャッジマン・ヒルダ・ポケギア3.0・ハイパーボール・ポケパッドを一律ゲート
- `_score_option()`のLunatone特性（ルナサイクル）分岐を`_safe_draws(my_state) >= 3`方式に変更
- 旧`DECK_SAFETY_THRESHOLD`定数を完全に削除（`main.py`・テストファイルの両方から参照ゼロを確認済み）
- 暗号マニアの解読・ワイの思いやり・夜のタンカは山札に触れない/山札枚数を変えない効果のため、意図的にゲート対象外のまま維持
