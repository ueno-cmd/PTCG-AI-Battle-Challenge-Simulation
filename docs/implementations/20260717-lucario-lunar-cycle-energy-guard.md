# ルカリオexエージェント ルナサイクル発動条件の修正 実装サマリー

## 背景

ユーザーから「トラッシュする際にエネルギーを優先している。しかも手札に1枚しかないときも」という不具合報告を受け、実バトルログ20件（`86456814`〜`86468342`）を`systematic-debugging`で調査した。

## 原因調査

- `SelectContext.DISCARD`で選択肢がエネルギー1種類だけに絞られている場面を20ログ全体で機械的に抽出したところ**58件**該当し、**全件が`effect.id=675`（Lunatoneの特性）による強制トラッシュ**だった（他原因は0件）
- `data/JP_Card_Data.csv`で公式カードテキストを確認：
  - ルナトーン特性「ルナサイクル」＝「自分の場に**ソルロックがいて**、自分の手札から基本【闘】エネルギーを1枚トラッシュするなら、山札を3枚引く」
  - ソルロックのワザ「コスモビーム」＝「自分のベンチにルナトーンがいないなら失敗」（コンボ関係。こちらは`calc_attack_plan`に実装済みで問題なし）
- `src/lucario_agent/main.py`の`_score_option`（`OptionType.ABILITY`分岐、Lunatone判定）は`_safe_draws(my_state) >= 3`（山札枚数）しか見ておらず、**手札のエネルギー枚数を一切チェックしていなかった**ことが直接の根本原因。カードテキスト上は「トラッシュするなら」という任意効果であり、"今それをやって良いか"の判断はエージェント側の責務だが、その判断ロジックが欠落していた
- 副次的に、カードテキストが要求する「ソルロックが場にいること」の条件もコードには実装されていなかった。ただし実ログ確認では、ゲームエンジン側が非合法な選択肢（ソルロック不在時のルナサイクル）をそもそも提示しないため、これによる実害は確認されなかった（防御的実装として合わせて追加）

## 修正内容

`_score_option`のLunatone判定に2条件を追加：

```python
if card.id == Lunatone:
    lunar_cycle_ready = (
        field_counts[Solrock] >= 1 and hand_counts[Basic_Fighting_Energy] >= 2
    )
    return 8500 if _safe_draws(my_state) >= 3 and lunar_cycle_ready else -1
```

- `field_counts[Solrock] >= 1`：カードテキスト通りソルロックが場にいることを要求
- `hand_counts[Basic_Fighting_Energy] >= 2`：手札に予備（2枚以上）が無ければ発動を抑制し、最後の1枚を守る

## テスト結果

- `TestLunaCycleAbilityScore`に新規2件追加（ソルロック不在時の抑制／手札エネルギー1枚時の抑制）、既存3件は新しい前提条件（ソルロック在席・エネルギー2枚）に合わせて更新
- RED確認後、最小修正でGREEN化
- リポジトリ全体 `uv run pytest -q`：513件、全PASS（回帰なし）
