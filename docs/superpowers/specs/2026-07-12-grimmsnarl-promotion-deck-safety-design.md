## 背景（ログ分析で確定した敗因）

直近ログ12件（85532486〜85541203、全てルールベース版の対戦・デッキ一致確認済み・クラッシュなし）の分析結果：

1. **テンポ負けが敗因の主軸**：負け10試合中8試合で相手はT2〜T3に初攻撃。自分の初攻撃はT5〜T13（3試合は攻撃ゼロ）。勝ち2試合は自分がT3〜T4に攻撃開始
2. **立ち往生（レイヤー②ターン計画の欠落）**：「アクティブが攻撃不能なのにベンチに攻撃可能ポケモンがいる」手番が負け10試合中7試合で発生。最悪例85534500では、エネ0のキチキギスexを壁にしたまま**ベンチのオーロンゲにエネルギーを6枚積み続け、一度も前に出せずに敗北**
3. **RETREATスコア強化だけでは4割空振り**：立ち往生134手番中、エンジンがRETREAT選択肢を提示していたのは63%。残り37%はアクティブがエネ0でにげるコストを払えず選択肢自体が不存在（85534500では11手番中0回提示）。→ 交代先選出（TO_ACTIVE）で壁を選ばない予防が本丸
4. **ボスの指令の早出し浪費**：負け6試合でT2〜T5にボスを使用。攻撃手段ゼロの時点で引きずり出してもダメージなし、代わりにドローサポートを使う権利を失い展開がさらに遅延
5. **山札セーフティの欠落（レイヤー④）**：85541203は山札0のデッキアウト負け（手札にRare Candy3枚死蔵）。85534500も12ターンで山札残3の寸前
6. RL版（evo_search）の攻撃回数ゼロ問題とは原因が別（RL=準備をサボる／本件=準備完了アタッカーを昇格しない）。RL側の再深掘りは不要

## 設計

### 1. 新設ヘルパーと定数（全修正の共通語彙）

```python
# ワザの必要エネルギー数（本デッキは全て悪エネで支払える。CSVで実測確認済み）
ATTACK_COSTS = {
    Grimmsnarl_ex:  2,  # Shadow Bullet {D}{D}
    Fezandipiti_ex: 3,  # Cruel Arrow ●●●
    Marnie_Morpeko: 3,  # Spiky Wheel ●●●
    Yveltal:        1,  # Clutch {D}
}

def _is_attack_ready(pokemon) -> bool:
    """このポケモンは装着済みエネルギーで攻撃できるか"""
    need = ATTACK_COSTS.get(pokemon.id)
    return need is not None and len(pokemon.energies) >= need

# セルフ対戦A/B用フラグ。校正ノートブックがTUNABLE_WEIGHTSと同じ
# clear()+update()方式で差し替える。全てTrueが本番設定
FEATURE_FLAGS = {
    "attacker_promotion": True,  # 修正①②
    "boss_attack_gate":   True,  # 修正③
    "deck_safety":        True,  # 修正④
}
```

- `FieldState`に3フィールド追加：`my_deck_count` / `my_prize_left`（自分の残りプライズ枚数）/ `my_hand_count`。いずれもobservationの`current.players[my_index]`から取得
- 期待ダメージ算出ヘルパー（修正①の同点比較用）：オーロンゲ180／キチキギス100／モルペコ20+40×エネ／イベルタル20（Clutch）。既存の`SHADOW_BULLET_DAMAGE`等の定数を再利用

### 2. 修正①② 交代先選出とRETREAT昇格

`_score_own_switch_target()`の優先順位（`FEATURE_FLAGS["attacker_promotion"]`がFalseなら現行式のまま）：

| 優先 | 条件 | スコア |
|---|---|---|
| 1 | Crustle対面のモルペコ | 20000 + エネ×2（現行維持） |
| 2 | **攻撃準備完了のアタッカー（新設）** | **12000 + 期待ダメージ** |
| 3 | 未準備のオーロンゲ | 10000 + エネ×2（現行維持） |
| 4 | 特性専用ポケモン | -1000 + HP（現行維持） |
| 5 | その他 | HP + エネ×2（現行維持） |

RETREATスコアリング（`OptionType.RETREAT`分岐）に第3条件を追加（こちらも`FEATURE_FLAGS["attacker_promotion"]`でゲート）：

```
現行: (オーロンゲ瀕死) or (Crustle対面×ex攻撃者×モルペコ在ベンチ) → 3000
追加: アクティブが攻撃不能（_is_attack_ready=False）かつ
      ベンチに攻撃準備完了アタッカーがいる → 3000
```

逃げた後の交代先選出は修正①の新基準が受け持つため、①と②が連動して「壁の監禁」を防ぐ。RETREATが提示されない37%のケースは、修正①がきぜつ後の交代（TO_ACTIVE）で壁を選ばなくなることで発生源から減らす。

スコア整合の確認：アクティブが攻撃可能なら昇格条件は偽になるためATTACK（2000/5000）と競合しない。キチキギスexの特性（2500）はターンを消費しないためRETREAT(3000)より低くても実害なし（MAIN再訪後にRETREAT可能）。

### 3. 修正③ ボスの指令の攻撃可否ゲート

`_score_play()`のボス分岐の冒頭にゲートを追加（`FEATURE_FLAGS["boss_attack_gate"]`がFalseなら現行のまま）：

```
アクティブが攻撃準備完了でない場合 → -1（温存）
（KO確定判定8800・ε探索6000の判定に入る前に弾く）
```

「引きずり出したターンに自分が攻撃できること」をボス使用の前提条件にする。

### 4. 修正④ 山札セーフティ（battlecore B式）

```python
def _safe_draws(fs: FieldState) -> int:
    """残りターンの必須ドロー分を温存した、安全に消費できる山札枚数。
    残りプライズ数を残りターン数の見積もりとして使う"""
    return fs.my_deck_count - fs.my_prize_left - 1
```

山札を消費する札に消費量を定義し、`FEATURE_FLAGS["deck_safety"]`がTrueのとき**消費量 > _safe_draws(fs) なら-1（温存）**とする：

| カード | 山札消費量 |
|---|---|
| リーリエの決意 | `max(0, 引く枚数 − (手札枚数 − 1))`。引く枚数はプライズ残6なら8、それ以外6。手札−1は本札自身を除いて山札へ戻る分 |
| チェレン | 3 |
| Secret Box | 4 |
| ポケパッド / Team Rocket's Petrel / ギーマの一手 | 1 |
| Buddy-Buddy Poffin | 2 |
| ナイトストレッチャー | 0（トラッシュ回収。ゲート対象外） |
