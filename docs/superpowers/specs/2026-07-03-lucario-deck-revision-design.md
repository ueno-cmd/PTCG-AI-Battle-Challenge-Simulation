# ルカリオexデッキ 軽量版リビルド 設計書

**作成日：** 2026-07-03
**背景：** LBスコアが523〜676で乱高下し安定しない。バトルログ8件（83465939, 83484940, 83509359, 83509516, 83510250, 83534688, 83563077, 83574179）を解析した結果、勝敗は4勝4敗で、敗因は以下の2系統に整理できた。

1. **デッキアウト負け（2敗：83465939, 83484940）**：賞金レースで有利、または互角にもかかわらず自分の山札が0枚になり敗北。「カーマイン」（手札を捨てて5枚ドロー、1試合で6回使用）や「リーリエの決心」（手札を山札に戻して6〜8枚ドロー）を、山札残数を考慮せず無条件で高スコアにする現行の`_score_play_option`の設計が主因。
2. **速攻・高火力デッキへの対応不足（2敗：83534688, 83574179）**：
   - 83534688（対CurveCowboy／マリィのグリムスナールex系）：リオル3枚中2枚が自分のプライズに埋まる事故により、メガルカリオexが一度も攻撃せず盤面全滅。
   - 83574179（対TAKUTO INOUE／アラカザム）：唯一のメインアタッカーだったメガルカリオex（3賞金分）を一撃で失い敗北。ベンチには温存されたエネルギー3個のハリテヤマがいたが未使用のまま終戦。

なお、メガルカリオex自体は勝ち試合ではターン3〜4で立ち上がっており、デッキ設計自体は正しくアグロとして機能している。問題は「デッキアウトを誘発する無条件ドロー」と「事故時のリカバリー手段の薄さ」である。

ユーザーから、2026-07-02大会優勝デッキをベースにした軽量プラン（マクノシタ・ハリテヤマ系統を撤去し、リオル/メガルカリオex/ソルロック/ルナトーンの4本柱に絞る構成）が提示された。本設計はこれを採用し、あわせてエージェントロジックをルールベース＋コンテキストバンディット（ε-greedy）のハイブリッドに刷新する。

## 3. ルナサイクル（ルナトーンの特性）の新規実装

現行エージェントには特性の個別判定ロジックがほぼ無い（`OptionType.ABILITY`は`card.id == 1267`（Lumiose City）以外は一律30000点を返す汎用実装）。以下を新規実装する。

- **発動条件**：ソルロックが場におり、かつ手札に基本闘エネルギーが1枚以上ある
- **フロー**：ABILITY選択 → 手札の基本闘エネルギー1枚をトラッシュする選択（`SelectContext.DISCARD`、`area == AreaType.HAND`の場合を基本闘エネルギー優先で選択）→ 山札3枚ドロー
- **優先度**：4節のデッキアウト防止ゲートの対象とする（山札消費効果のため）
- 実装時、実際にログ/simulatorで発火するSelectContextが上記と異なる場合は挙動を実機確認の上で対応する

## 4. デッキアウト防止ゲート（共通関数）

今回の敗因調査の主因だった「無条件の大量ドロー」を防ぐため、共通ロジックを用意し、山札消費が大きい2つの効果に適用する。

```python
DECK_SAFETY_THRESHOLD = 15  # 山札残数がこれ未満なら大量ドロー系を抑制

if deck_count < DECK_SAFETY_THRESHOLD:
    score = -1  # 抑制
else:
    score = base_score  # 通常優先度
```

- **リーリエの決心**：山札残数 < 15 なら -1、それ以外は通常スコア
- **ルナサイクル**：山札残数 < 15 なら抑制、それ以外は通常優先度で使用

しきい値15枚は初期値。実戦バトルログで有効性を確認し、次回以降調整する。

## 5. コンテキストバンディット／ε-greedy適用

`src/grimmsnarl_agent/main.py`のボスの指令ロジック（`EPSILON = 0.28`、テスト用に`_rng: random.Random`を注入可能にする設計）と同じパターンを踏襲する。

### ボスの指令
```python
if 相手ベンチに対象なし:
    return -1  # 温存
if 確定KO対象あり（現在の攻撃プランのremain_hp <= 0）:
    return 8800  # 即使用
if rng.random() < EPSILON:
    return 6000  # 探索的先出し
return -1  # 温存
```

### メガブレイブ（270ダメ・2エネルギー・同一ポケモンで2ターン連続使用不可）
- 通常攻撃（130ダメ、1エネルギー）で確定KOが取れるなら、メガブレイブは温存（クールダウンを節約し安い方を優先）
- メガブレイブでしか取れない確定KOがあるなら即使用
- どちらでも確定KOが取れない場合は、ε-greedyで先出し（圧をかける）か温存かを決定

### ルナサイクル
- 4節のデッキ残数ゲートのみを適用（ε-greedyは使用しない。発動判定は不確実性のある駆け引きではなく、残りターン数から逆算できる計算問題のため決定的しきい値判定とする）

`EPSILON`値・`_rng`注入の仕組みはGrimmsnarlの実装をそのまま流用する。
