# ルカリオexデッキ ロック闘エネルギー導入設計書（Alakazam対策）

## 背景・目的

`docs/analyses/20260719-lucario-post-fix-20-games-analysis.md`の実戦解析で、Alakazam（フーディン）系デッキとの対戦成績は1勝3敗（25%）と依然最悪の対面と判明した。

原因はフーディンの技「ハンドパワー」（闘コスト1、`data/JP_Card_Data.csv`原文：「自分の手札の枚数×2個ぶんのダメカンを、相手のバトルポケモンにのせる」）。基本ダメージが存在しない完全効果ベースの技で、弱点・抵抗力を無視して相手のバトルポケモン（アクティブのポケモン）を一撃で沈める。2026-07-18のジャッジマン改修（相手手札枚数トリガー＋DISCARD保護）は実装として正しく機能していることを実戦ログ2件（`86608608`, `86611274`）で確認済みだが、ジャッジマンがデッキに2枚しかない構造的制約（ドロー運での未使用、または1枚使用時に効果自体でもう1枚も山札へ戻ってしまう）により根本解決には至っていない。

ユーザーが実際のジムバトル環境から発見した**ロック【闘】エネルギー**（ID20、特殊エネルギー）を採用し、ハンドパワーそのものを無効化することが本設計のゴールである。

> ロック【闘】エネルギー（`data/JP_Card_Data.csv`原文）：
> 「このカードは、ポケモンについているかぎり、【闘】エネルギー1個ぶんとしてはたらく。このカードをつけている【闘】ポケモンは、相手のポケモンが使うワザの効果を受けない。（すでに受けている効果は、なくならない。）」

闘エネルギー1個分として機能するため攻撃コストへの影響はなく、装着した闘タイプポケモンは相手の技の"効果"（ハンドパワーのダメカン設置を含む）を受けなくなる。

**スコープ外（今回は対象としない）**：カイオーガ＋メガユキノオー対策、メガジガルデex＋コアメモリの採用検討、ロケット団の監視塔の採用検討。いずれも将来の別ブレストで扱う。

## エージェントロジック変更（`src/lucario_agent/main.py`）

設計にあたり、既存コードで「闘エネルギー」を暗黙的に基本闘エネルギー（ID6）のみで判定している箇所を全数調査した。カード原文と突き合わせ、変更が必要な箇所と不要な箇所を以下の通り確定する。

### 新規対応（5件）

1. **`_score_attach_option`**：ロック闘エネルギー（新規定数`Rock_Fighting_Energy = 20`）をアクティブのポケモンに装着する場合にボーナス加点する分岐を追加する。既存のHero's Cape分岐と同じ構造（`card.id`で早期判定してreturn）を踏襲する。ハンドパワーはアクティブのポケモンのみを狙う技のため、「そのときアクティブの子を優先的に守る」という2026-07-19会話で承認済みの方針に対応する
2. **`calc_attack_plan`の先読み（319行目）**：「あと1エネルギーで技が届くか」の判定が`hand_counts[Basic_Fighting_Energy] >= 1`のみを見ている。手札にロック闘エネルギーしか無い場合に「エネルギー無し」と誤判定し攻撃候補を見落とす潜在バグのため、`hand_counts[Basic_Fighting_Energy] + hand_counts[Rock_Fighting_Energy] >= 1`に修正する
3. **`JudgePolicy.play_score`の自己都合トリガー（579行目）**：「手札に闘エネルギーが1枚も無い」判定が同様に基本のみを見ている。ロック闘エネルギーを1枚保持していても「エネルギー切れ」と誤判定してジャッジマンを不要に切ってしまう恐れがあるため、同様に合算判定へ修正する
4. **`SelectContext.DISCARD`（441-442行目）**：ロック闘エネルギーは現状デフォルトの10点（＝捨てやすい）で無防備。夜のタンカ（`data/JP_Card_Data.csv`原文：「自分のトラッシュから**ポケモンまたは基本エネルギー**を1枚選び」）では回収できず、一度捨てると恒久的に失う。基本闘エネルギーは「手札に2枚以上あれば50点（捨てて良い）／それ未満なら-20点（温存）」だが、ロック闘エネルギーは回収不可・デッキ内4枚のみという希少性を踏まえ、**手札枚数によらず常に-20点（常時温存）**とする
5. **`SelectContext.TO_HAND`（434-435行目）**：トウコ（`data/JP_Card_Data.csv`原文：「自分の山札から進化ポケモンと**エネルギー**を1枚ずつ選び」＝"基本"限定ではない）でロック闘エネルギーをサーチできる場面がある。コスト機能は基本闘エネルギーと同等で追加の保護効果もあるため、基本闘エネルギーより優先して手札に加えるボーナスを追加する

### 確認したが変更不要（カード原文で裏取り済み）

- **メガルカリオexの技「はどうづき」の効果（293行目、`discard_counts[Basic_Fighting_Energy]`）**：カード原文「自分のトラッシュから**「基本【闘】エネルギー」**を3枚まで選び、ベンチポケモンに好きなようにつける」と明記されており、ロック闘エネルギーは対象外が正しい仕様。変更しない
- **ルナトーンの特性「ルナサイクル」の発動条件（702行目、`hand_counts[Basic_Fighting_Energy] >= 2`）**：カード原文「手札の**基本**闘エネルギーを1枚トラッシュするなら」と明記されており、同様にロック闘エネルギーは対象外が正しい仕様。変更しない
- **ファイトゴングの山札サーチ**：カード原文で「**「基本【闘】エネルギー」**を1枚選び」と明記されており、ロック闘エネルギーはサーチ対象外が正しい仕様。エージェントコード側に個別分岐はなく対応不要
- **`scripts/build_deck.py` / `scripts/build_lucario_selfcheck_notebook.py`**：カードIDをハードコードせずDECKリストを汎用的に処理しているため変更不要

## テスト方針

- `tests/test_lucario_deck.py`：`test_energy_count`を基本闘エネルギー7枚・ロック闘エネルギー4枚（Fighting系合計11枚）を検証する形に更新
- `tests/test_lucario_agent.py`：上記「新規対応」5件それぞれに対し、挙動を確認する単体テストを追加する
  - ATTACH優先度：手札に基本闘エネルギーとロック闘エネルギーが両方あり、アクティブへの装着オプションが両方提示された場合にロック闘エネルギー側が高スコアになること
  - `calc_attack_plan`：手札にロック闘エネルギーのみ（基本闘エネルギー0枚）の状態で、1エネルギー不足の攻撃候補が正しく候補に残ること
  - `JudgePolicy`：手札にロック闘エネルギーのみの状態で自己都合トリガー（`hand_counts[...] == 0`起因）が発火しないこと
  - DISCARD保護：ロック闘エネルギーの保護スコアが基本闘エネルギーの保護スコア以上であること
  - TO_HAND優先度：ロック闘エネルギーと基本闘エネルギーが同時に選択肢にある場合、ロック闘エネルギー側が優先されること
- リポジトリ全体`uv run pytest -q`で既存517件＋新規テストが全てPASSすることを確認する（回帰なし）
