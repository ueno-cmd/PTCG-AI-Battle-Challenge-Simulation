# ジャモライコエージェント エネルギー運用ロジック修正 設計書

## 背景

`docs/reviews/`や過去のメモリの通り、ジャモライコエージェントはKaggle上の校正実験（vs イオナサンプル200試合）で勝率0.015という壊滅的な結果だった。`OptionType.CARD`スコアリング追加後も勝率は変化しなかったため、校正ノートブックに手番選択ログ出力機能を追加し（[[project-ptcg-competition]]参照）、実際にダウンロードした10試合分のログを解析した。

### ログ解析で判明した事実

- 10試合・312回のMAIN判断のうち、`ATTACK`という選択肢自体が提示されたのはわずか32回（10.3%）。ジャモライコはほとんどの試合で「準備」だけして終わっている
- **タイカイデン（Iono's Kilowattrel, ID271）の自滅ループ**：特性「フラッシュドロー」（自分についた基本雷エネルギーを1個トラッシュして手札を6枚まで引く）を、エネルギーを付けた直後の同じターン内に発動し、たった今付けたエネルギーを自分で捨ててしまうパターンを実ログで複数回確認（game0のturn15・turn17で同一パターン）。タイカイデンが場に出ている119回の判断中、攻撃圏内（3エネルギー）に到達できたのはわずか2回（1.7%）
- **タケルライコex（Raging Bolt ex, ID63）がほぼ一度もダメージを与えていない**：92回の判断中、エネルギーが1枚を超えたことが一度も無い

### カード効果の裏取りで判明した設計上の見落とし

`data/JP_Card_Data.csv`で該当カードの効果文・カテゴリを確認した結果、以下が判明した：

1. **タケルライコexは「ナンジャモのポケモン」ではない**（カテゴリ：古代 vs 他5体は「トレーナーのポケモン（ナンジャモ）」）。そのためハラバリーexの特性「エレキストリーマー」（自分の手札から基本【雷】エネルギーを1枚選び、自分の**『ナンジャモのポケモン』**につける）はタケルライコexには使えず、ビリリダマの「チェインボルト」のダメージボーナス（**『ナンジャモのポケモン』**全員についている雷エネルギーの数×20）もタケルライコexのエネルギーは対象外
2. **「きょくらいごう」の追加ダメージは自分の場のポケモン全体が対象**：効果文は「自分の**場のポケモン**についている基本エネルギーを好きなだけトラッシュし、その枚数×70ダメージ」であり、タケルライコex自身に限定されていない。したがってタケルライコex自身は技のコスト（雷1闘1）を満たす最低限のエネルギーだけ持っていればよく、追加ダメージはベンチのハラバリーex/タイカイデンに（特性で無料で）貯めた分から捻出できる
3. `_score_option`の`match`文で**`OptionType.ENERGY`（きょくらいごうの捨てエネルギー選択で使われる型）が一つもケース分けされておらず、常にスコア0**になっていることが判明。これはジャモライコ初回実装時の`OptionType.CARD`丸ごと未実装（勝率0.015の原因）と同種の抜け漏れ

## 修正方針

### 修正1：タイカイデンの自滅ループ防止

`_score_option`の`OptionType.ABILITY`・タイカイデン分岐に、「手札に基本雷エネルギーが1枚も無い時だけ許可」の条件を追加する。

- 手札に雷エネルギーがまだある＝今後もATTACHで攻撃圏内（3エネルギー）に伸ばせる見込みがある → フラッシュドローは使わせない（スコア-1程度）
- 手札に雷エネルギーが無い＝今ターンはこれ以上伸びる手段が無い → 従来通りデッキセーフティ（`_safe_draws`）の範囲でフラッシュドローを許可

`FieldState`に「手札に基本雷エネルギーがあるか」を表すフラグ（例：`hand_has_basic_lightning_energy: bool`）を追加する想定。

### 修正2：デッキ変更（`decks/jamoraiko_20260713.py`）

- `(1119, 2)` エネルギー転送 → 削除
- `(1116, 2)` エネルギーつけかえ を新規追加（60枚維持）

**採用理由**：タケルライコexは通常の手張り（1ターン1回まで）でしか闘・雷エネルギーを受け取れない（ハラバリーexの特性は「ナンジャモのポケモン」限定で対象外のため）。「つけかえ」無しだと、闘エネルギーの手張り→（1ターン空けて）雷エネルギーの手張り、で最短2ターンかかる。「つけかえ」ありだと、ベンチのハラバリーex/タイカイデンに特性で自然に貯まっている雷エネルギーを同じターン内に転送できるため、闘エネルギーの手張り1回＋つけかえ1回で同一ターン内に着地できる（2ターン→1ターンのテンポ短縮）。

「エネルギー転送」（山札から基本エネルギー1枚をサーチして手札に加える効果。ポケモン間のエネルギー移動効果ではない）とは別カードであることをユーザーとの対話で確認済み。

### 修正3：タケルライコexへのエネルギー供給ロジック

`energy_score()`にタケルライコexの分岐を追加する：

```python
elif pokemon.id == Raging_Bolt_ex:
    if lightning_count < 1:
        score += 90
```

3枚まで貯める必要は無いことが判明したため、狙いは「雷エネルギー1枚を最速で確保する」ことのみに絞る（闘エネルギーは既存の`_score_attach_option`でスコア7000の最優先扱いになっている）。

`エネルギーつけかえ`のPLAYスコアリングを新規追加する：

- 発動条件：タケルライコexの雷エネルギーが0枚、かつベンチに「既に自分自身の攻撃条件を満たしていて余剰がある」ナンジャモポケモン（例：ハラバリーexなら4枚以上、タイカイデンなら3枚以上）が存在する時のみ高優先度
- 供給元が見つからなければ低優先度（無理に使わない）
- 実際の「どのポケモンから外すか／どこに付けるか」を選ぶCARD系サブ選択（`ATTACH_FROM`/`ATTACH_TO`相当のコンテキスト）にも、「供給元＝余剰ありのナンジャモポケモン」「宛先＝タケルライコex」を反映するスコアリングを追加する

### 修正4：`OptionType.ENERGY`（きょくらいごうの捨てエネルギー選択）の新規実装

`_score_option`の`match`文に`case OptionType.ENERGY:`を追加する。**まずはシンプルに「提示された基本エネルギーは常に捨てる（貪欲方針）」**とする：

```python
case OptionType.ENERGY:
    return 9000  # きょくらいごうの追加ダメージ用：提示された基本エネルギーは常に捨てる
```

ターン内状態追跡（他ポケモンの将来の攻撃に必要な分を温存する等）は行わない。理由：

- 実バトルログでこの型（`SelectContext.DISCARD_ENERGY`）が実際に出た例がまだ無く、設計段階でこれ以上複雑化する根拠が無い
- きょくらいごうは大ダメージの決め手として使う想定であり、「出し惜しみせず全部使う」方針は妥当性が高い
- 過去メモリに記録されている「ターン内状態追跡が必要な複雑実装」はv2以降の改善対象とし、今回はまず貪欲方針で実装してKaggle実測してから判断する

### 修正5：タケルライコexの「はじけるほうこう」抑制

`OptionType.ATTACK`のタケルライコex分岐に、以下の条件を追加する：

- 手札に闘エネルギー・雷エネルギーのどちらも無く、かつ使える「エネルギーつけかえ」の供給元も無い時のみ「はじけるほうこう」（ダメージ0、手札全トラッシュして6枚引き直し）を許可
- それ以外（まだきょくらいごうの着地に伸びる見込みがある間）は温存する
- きょくらいごう自体や他のポケモンの技のスコアリングには影響しない

## スコープ外（今回はやらないこと）

- ドラパルドex・イワパレス（Crustle）・フーディン（Alakazam）との実対戦速度・タケルライコex撃破後の立て直し力（resilience）の検証・設計は、今回の修正をKaggleで実測してから着手する
- `OptionType.ENERGY`のターン内状態追跡（他ポケモンの将来の攻撃余力を残す形の高度な取捨選択）は今回見送り、貪欲方針の実測結果を見てから判断する
- `TOOL_CARD`（`OptionType`値4）の未実装は今回のデッキには関係するツールカードが無いため対象外のまま

## テスト方針

- 修正1（タイカイデン自滅防止）：`FieldState`の新規フラグ・スコアリング分岐に対する単体テスト。手札に雷エネルギーがある/ない両ケースでのスコア差を検証
- 修正2（デッキ変更）：既存のデッキ枚数テスト（60枚・ACE SPEC制限等）が新構成でも通ることを確認
- 修正3（タケルライコexエネルギー供給）：`energy_score()`の新規分岐、`エネルギーつけかえ`のPLAY/CARD系スコアリングそれぞれに単体テスト（供給元あり/なしのケース含む）
- 修正4（`OptionType.ENERGY`実装）：`_score_option`の新規caseに対する単体テスト
- 修正5（はじけるほうこう抑制）：闘・雷エネルギーの有無、つけかえ供給元の有無の組み合わせでスコアが正しく変わることを検証
- 既存の451件のテストスイート全体の回帰確認（`uv run pytest -q`）
- ローカルでは`libcg.so`が動かないため実対戦での検証は不可能。修正完了後、既存の校正ノートブック（`jamoraiko_vs_iono_experiment.ipynb`、手番選択ログ出力機能つき）を再ビルドし、Kaggle上で再実行して勝率変化とログ内容を確認することを次のステップとする
