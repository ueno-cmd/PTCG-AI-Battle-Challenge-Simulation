# マリィのグリムスナールex デッキ フェーズB：デッキ構成見直し 設計書

**作成日：** 2026-07-03
**背景：** フェーズA（`docs/implementations/20260703-grimmsnarl-switch-scoring-fix.md`）でSWITCH/TO_ACTIVEの同点デフォルト選択バグを修正したが、調査（`docs/reviews/20260703-grimmsnarl-switch-scoring-investigation.md`）の中で「特性専用・バトル場を想定しないポケモンの座組が厚く、バグの影響範囲を広げている」という仮説が挙がった。本設計はその仮説に基づき、座組を整理してバグの影響範囲自体を減らすことを目的とする。

---

## ゴール

特性専用ポケモンを整理して「攻撃・戦線維持ができるポケモン」の比率を上げ、フェーズAで修正した"弱いポケモンが前に出る"問題の影響範囲そのものを縮小する。キチキギスex(140)の採用はこのゴールに資する範囲で検討する（付随的な位置づけ）。

## 検討の経緯

現行デッキの特性専用ポケモン5種（ユキメノコ104／スボミー235／シェイミ343／シャリタツ122／コダック858）を、①実際のバトルログでの誤選出履歴、②今回の方針（弱いポケモンを前に出さない）との適合度、の2軸で評価した。

| カード | 誤選出履歴 | 方針との適合度 |
|---|---|---|
| スボミー(235) | あり（30HPで前に出た：`83347688` step91） | 低（1ターン限定効果、状況依存） |
| コダック(858) | あり（被弾済40HPで前に出た：`83438721` step125） | 低（自傷特性対策は現環境で刺さる場面が薄い） |
| シャリタツ(122) | 候補として選ばれかけた | 低（特性発動に「バトル場にいること」が必須で方針と根本的に矛盾。実物TCGでも"弱いから隠す"ではなく"捨て駒的に先発させて仕事をさせる"運用が定番であり、今のエージェント設計とは相容れない） |
| シェイミ(343) | なし | 中（ベンチ特性要員を技ダメージから守り、方針と親和性がある） |
| ユキメノコ(104)系 | なし | 高（マシマシラとの周回コンボ〔フロスラスが全特性持ちにダメカン付与→マシマシラが最大3個相手に転嫁〕の起点） |

検討したアプローチ：

- **A（最小限）：** 誤選出の実害が出たスボミー・コダックのみ削減
- **B（採用）：** スボミー・コダック・シャリタツの3枚を削減し、空いた枠にキチキギスex(140)を採用
- **C（保守的）：** 削減はせず、ユキメノコ系の枚数のみ絞る

Bを採用。理由：3枚とも「誤選出の実害」または「方針との根本的矛盾」のいずれかに該当し、整理の妥当性が高い。空いた枠は210HPの高耐久かつ実際に攻撃可能（無色3（本デッキは全て悪エネルギーのため悪3枚で支払える）でクルーエルアロー100ダメ）、特性（前ターンに自分のポケモンがきぜつしていれば発動、バトル場条件なし）も安全なキチキギスexで埋めることで、単なる頭数減らしに終わらせず火力・耐久を底上げできる。

## 変更内容②：エージェントロジック追従（`src/grimmsnarl_agent/main.py`）

**①定数整理**
- `Budew`/`Tatsugiri`/`Psyduck` の定数と `SUPPORT_ONLY_IDS` からの参照を削除（20260702改修で確立した「削除カードの死んだ参照を残さない」方針を踏襲）
- `Fezandipiti_ex = 140` を新規追加

**②エネルギー配分（`_score_attach`）**
グリムスナールexの攻撃分（悪悪＝2エネ）確保後、余剰の基本エネルギーをキチキギスexにも配分する：

```python
if pokemon.id == Fezandipiti_ex and energy_count < 3 and fs.grimmsnarl_energy_count >= 2:
    return 5000 - energy_count * 500
```

優先順位：グリムスナールex本体の攻撃分（常に最優先）＞ キチキギスexへの配分 ＞ マシマシラへの配分（既存）。メインアタッカーの攻撃を絶対に阻害しない既存方針を踏襲。

**③攻撃スコアリング（`_score_attack`）**
`Shadow_Bullet_ID`と同じパターンで`Cruel_Arrow_ID`を`_build_card_table()`内で取得。相手フィールド（バトル場＋ベンチ）にHP100以下の確定KO対象がいれば高スコア、なければ通常スコア：

```python
if attack_id == Cruel_Arrow_ID:
    op_hps = [fs.op_active_hp, *fs.op_bench_hp]
    return 5000 if any(hp <= 100 for hp in op_hps) else 2000
return 1000
```

ダメージ先の選択（ベンチ低HP優先）は既存の`DAMAGE_COUNTER`ハンドラをそのまま流用し、追加変更は不要。

**④特性の優先度（`ABILITY`）**
「さかてにとる」はマシマシラと同格の優先度で常に使用する：

```python
score = 2500 if card.id in (Munkidori, Fezandipiti_ex) else 1200
```

**⑤SWITCH/TO_ACTIVEのスコアリングは変更不要**
キチキギスexは`SUPPORT_ONLY_IDS`に含めないため、既存のデフォルト式（`card.hp + len(card.energies) * 2`）がそのまま適用される。210HPは他の控えより高く出るため、グリムスナールex不在時の次善アタッカーとして自然に優先選出される（フェーズAの修正がそのまま活きる）。
