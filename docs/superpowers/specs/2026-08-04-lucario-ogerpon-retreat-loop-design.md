## 1. 解決する問題

オーガポンexが**バトル場でエネルギーを装着した同じターンに退却し、そのエネを退却コストで捨てる**動作が、
修正後バッチ（ver26+ver27の有効31戦）で**19枚**発生している。バトル場への全装着103回の約17%。

本セッションで実ログを追加計測したところ、この動作は単なるエネルギーの浪費ではなく、
**そのターンを丸ごと空転させている**ことが分かった。

| 計測（有効31戦・自分のターン297） | 値 |
|---|---|
| 「同ターン装着→退却でそのエネ破棄」をしたターン | **19回** |
| 　うち **そのターンに1回も攻撃できなかった** | **15回（79%）** |
| 　うち そのターンに攻撃できた | 4回 |
| 参考：全ターンで攻撃できた割合 | 40.1% |

退却先も悪い。19回中16回はオーガポンexから逃げており、その行き先は：

- **0エネのメガルカリオex … 9回**（3枚献上のexを、攻撃できない状態で前線に晒している）
- 0エネのルナトーン／ソルロック … 5回
- エネが乗っていて実際に攻撃できた … 4回のみ

またオーガポンexは**31戦で33回**バトル場に入っており（KO後の強制TO_ACTIVEが21回＝64%）、
うち27回は0エネ。ふうせん（Air Balloon）が付いていたのは**33回中2回**だけだった。

### 根本原因

実ログ `88778720` ターン7（step62〜66）を1ステップずつ確認して確定した。

```
step62  手札のエネは1枚のみ。装着先候補＝バトル場(オーガポンex 0エネ)とベンチ4体
        → バトル場のオーガポンexを選択（_score_attach_option の救済ボーナス +300 が発火）
step63  → 退却を選択（_score_retreat_option が 2000 を返す）
step64  → 退却コストとして、いま付けたそのエネを破棄
step66  メガルカリオexが0エネでバトル場へ。装着権は使い切りで攻撃できずターン終了
```

連鎖はこうなっている。

1. オーガポンexが0エネだと「にげる」が選択肢に現れない
2. → `_analyze_main_options` の `can_switch` が False
3. → `calc_attack_plan` が `if i != 0 and not can_switch: break`（`combat.py:161`）で
   **ベンチのアタッカーを一切検討しない**
4. → 攻撃プランなし（`current_plan.damage` は初期値 -1、`current_plan.energy` は False）
5. → `_score_attach_option` の救済ボーナス +300 が発火し、バトル場に1エネ装着
6. → 今度は「にげる」が選べるようになり、`_score_retreat_option` が退却を命じる
7. → コストとしてそのエネが消える。交代先は0エネ、装着権も無い＝**何もできない**

**芯にあるのは `combat.py:270-273` の温存退却分岐である。**

```python
if current_plan.damage <= 0 and my_active is not None and card_table is not None:
    data = card_table[my_active.id]
    if data.megaEx or data.ex:
        return 2000  # 無効化等で攻撃が無意味な高価値ポケモンを温存退却する
```

この分岐は 2026-07-07 に**イワパレス(Crustle)に技を無効化されて攻撃が無意味な場合**を
想定して書かれたものだが、実際には **「まだエネルギーが足りないだけ」でも発火する**。
`calc_attack_plan` はエネルギー不足のアタッカーを `continue` で読み飛ばすため、
`damage <= 0` が「無効化されている」と「準備できていない」の**両方を意味してしまっている**。

オーガポンexの技「ぶちやぶる」は闘エネ3個を要求するため、この誤認がほぼ常時成立する。
**「準備中」を「詰み」と誤判定しているのが根本原因。**

## 2. 変更内容

### 変更1（本丸）：温存退却を「本当に攻撃が無意味なとき」だけに限定する

`_score_retreat_option`（`src/lucario_agent/combat.py:266`）の温存退却分岐に、
**相手のバトル場がex無効化特性を持っていること**を条件として加える。

判定値 `op_active_nullifies_ex` は `_op_active_nullifies_ex`（`main.py:138`、
`EX_DAMAGE_NULLIFIER_IDS = {Crustle(345), Sylveon(330)}`）で既に算出済みで、
`_score_option` まで引数として渡ってきている。新たな状態計算は不要。

- **エネルギー不足で `damage <= 0` なだけの場合は退却しない**（`-1` を返す）
- **相手がex無効化持ちで、自分のアクティブがex の場合は従来どおり `2000` を返す**
  （イワパレス／ニンフィア対策の退行を防ぐ）
- `current_plan.attacker >= 1`（ベンチに攻撃できるアタッカーがいる）の分岐は**変更しない**

#### これで挙動がどう変わるか

| | 現在 | 変更後 |
|---|---|---|
| ターンN | 1エネ装着 → 退却 → **エネ消滅**。0エネのメガルカリオexが前線へ。攻撃なし | 1エネ装着（オーガポンexに残る）。退却しない。**210HP・2枚献上の壁が前線に残る** |
| ターンN+1 | 装着 → 攻撃 | アクティブに1エネ乗っているので `can_switch` が True になり、ベンチのアタッカーが攻撃プランに乗る → **前ターンのエネで退却コストを払い、今ターンの装着権はアタッカーに使える** → 攻撃 |

**デッドロックは発生しない。** ターンN+1 の時点でオーガポンexには1エネ乗っており、
`can_switch` が True になるため `calc_attack_plan` はベンチを検討する。
ベンチのアタッカーが攻撃可能なら `current_plan.attacker >= 1` の既存分岐（`2000`）で退却する。
ベンチが誰も攻撃できない場合は退却せず居座るが、そのときエネルギーは
ベンチのメガルカリオex（`energy_score` で 8000+1+100 = **8101**）がバトル場のオーガポンex
（8000+10+80 = **8090**。救済は `not pokemon.energies` が条件なので2個目には発火しない）を
上回るため、**エネルギーはアタッカー側に回る**。オーガポンexは1エネを保持したまま壁として立ち、
そのエネが後で自分の退却コストになる。

なおこの大小関係は `attacker1`（場のリオル／メガルカリオexの誰かが**2エネ以上**持っている＝
メガブレイブ可能、`main.py:112-120`）が False のときのもの。`attacker1` が True だと
オーガポンexが +40、メガルカリオexが -50 されて逆転するが、そのときは既に攻撃可能な
アタッカーが場にいるので `current_plan.attacker >= 1` の分岐で退却が成立し、
本設計が問題にしている「何もできない状態」には入らない。

### 変更2（補助）：ふうせん（Air Balloon）をオーガポンexへ優先装着する

オーガポンexのにげるコストは **1**、ふうせんは **-2**。1枚貼るだけでにげるコストが **0** になり、
エネルギーを一切払わずに出入りできる。KO後の強制交代で前に出ても即座に無償で下がれるため、
変更1と合わせて「何もできない状態」をさらに減らせる。デッキにふうせんは2枚、オーガポンexも2枚。

`_score_attach_option`（`main.py:525-534`）のどうぐ装着スコアの順位を次のとおりにする。
既存の同点（Maximum Belt→リオル と ふうせん→メガルカリオex がともに 7100）も併せて解消する。

| 装着 | 現在 | 変更後 | 意図 |
|---|---|---|---|
| Maximum Belt → メガルカリオex | 7200 | 7200（据置） | メガブレイブ270+50=320のワンパンが最優先 |
| **ふうせん → オーガポンex** | 6900 | **7150（新規）** | にげるコスト1→0。本設計の要 |
| Maximum Belt → リオル | 7100 | 7100（据置） | 進化後もどうぐは残るため次点 |
| ふうせん → メガルカリオex | 7100 | **7050** | 上記との同点を解消 |
| ふうせん → リオル | 7000 | 7000（据置） | |
| Maximum Belt → その他 | -1 | -1（据置） | ACE SPEC1枚の浪費防止 |
| ふうせん → その他 | 6900 | 6900（据置） | |

すべて 7000 番台に収まり、エネルギー装着（8000〜8930）・Judge(9000)・EVOLVE(9100+) の
帯域は侵さない。2026-07-28 に立てた不変条件「9000〜10000は空」を維持する。

### 変更3：呼び出し側の追従

`_score_retreat_option` に `op_active_nullifies_ex` 引数を追加することに伴い、
呼び出し箇所2つを追従させる。**片側だけ直す事故を防ぐため、両方を1つのタスクで扱う。**

1. `_score_option` の `case OptionType.RETREAT`（`main.py:624-629`）
2. **`SwitchPolicy.play_score`（`main.py:432-441`）** — Switchカードは
   `_score_retreat_option` の戻り値をそのまま発火条件に使う構造になっている

**SwitchPolicy も同じ条件で止まるのが正しい。** 0エネのオーガポンexから0エネのメガルカリオexへ
逃げるためにデッキに1枚しかないSwitchを切るのは、「何もできない」状態を維持したまま
カードだけ失う動きだからである。`current_plan.attacker >= 1`（ベンチのアタッカーが本当に
攻撃できる）ときは従来どおり発火する。

## 4. 効果測定（次のバッチ）

[[feedback_process_metrics_over_winrate]] のとおり、勝率では効果を判定できない
（40%→60%の真の改善でも20戦で検出できる確率は14.3%、検出力80%には各群97戦が必要）。
**狙った挙動が何回消えたか**で判定する。

提出は同一ロジックを時間差で2回行い **20戦×2＝40戦** を確保する（既定の運用）。
解析時は **相手の事故勝ち（勝ち試合のうち終局時の自分のサイド残が6のもの）を必ず除外**する
（罠8。除外を怠ると1ターンあたり指標が一律2割水増しされる）。

| 指標 | 計測手段 | 現在 | 期待 |
|---|---|---|---|
| **同ターンに装着したエネを退却で失った枚数**（主指標） | `measure_retreat_energy_loss()` の `lost_attached_same_turn` | 19枚/31戦 | ほぼ0 |
| 「装着→退却」ターンのうち攻撃できなかった数 | **新規計測が必要** | 15/19 | 事象自体が消える |
| 攻撃できたターンの割合 | **新規計測が必要** | 40.1% | 上昇 |
| オーガポンexへのふうせん装着率 | **新規計測が必要**（変更2の測定用） | 2/33回 | 上昇 |
| 自力のサイド勝ち（分散の小さい勝敗指標） | 既存の解析手順 | 8件/31戦 | 監視のみ |

**新規計測3つは `scripts/analyze_lucario_energy_metrics.py` への追加が必要。**
これは②提出物が変わらない作業なので、実装計画では①の作業と明確に分けて扱う。

## 5. 明記しておく懸念

**オーガポンexがバトル場に残る時間は増える。** 210HP・2枚献上・特性「いしずえのかまえ」
（特性持ちポケモンからの技ダメージを無効化）という性質から、0エネのメガルカリオex
（340HP・**3枚献上**）を前線に晒すより良いと判断しているが、これは実測で確かめるべき仮説である。
上表の「攻撃できたターンの割合」と「自力のサイド勝ち」で監視する。

もし悪化した場合の次の打ち手は、本セッションで見送った**案B「交代先が今ターン実際に
攻撃できるときだけ退却する」**（0エネのメガルカリオexを前に出さない）になる。
ユーザー判断により今回はスコープ外とした。

## 6. スコープ外（今回はやらない）

- **案B：交代先の質を見る退却判断**（上記のとおり次バッチの結果を見てから判断）
- **案C：オーガポンexをバトル場に出さない**（TO_ACTIVEの優先度引き下げ）。
  実測では代役も0エネばかりで、しかも110HP/80HPのため即座に落ちて次のKOで
  同じ状況に戻るだけなので、根本ではないと判断した
- **案D：デッキからオーガポンexを抜く**。イワパレス(Crustle)対策の唯一の手段を失う。
  なおハリテヤマへの差し替え案は闘エネ3個要求・にげるコスト3で
  **エネルギー問題の解決にならない**ことが既出
- `calc_attack_plan` が「退却コストの支払いがそのターンの装着権を消費すること」を
  計算していない件。変更1で実害の経路が塞がるため今回は触らない（記録のみ）
