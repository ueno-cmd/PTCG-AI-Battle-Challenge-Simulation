# battlecore-compact-agent 同梱エージェント2体のスコアリング設計分析

- 日付: 2026-07-12
- 分析対象: `src/rl_references/battlecore-compact-agent.ipynb`（Kaggle公開ノートブック、.gitignore対象）に
  zlib+base64圧縮で埋め込まれていた提出用エージェント2体のmain.py
  - A: ブリジュラスex＋エースバーン（鋼テンポ型、1102行）
  - B: フーディン／ノコッチ（手札×20ダメのドローエンジン型、911行）
- 比較対象: 我々の `src/grimmsnarl_agent/main.py`（509行）
- 安全性検査済み: 通信・外部コマンド・eval等の不審な処理なし。圧縮埋め込みは
  「検証済みビルドをバイト一致で配布する」ための工夫（sha256ハッシュ照合つき）
- ノートブックの性質: プロファイルA/Bを選んで実行するだけで`submission.tar.gz`が
  作られる「完成品配布型」。作者はローカルlibcgで対戦検証済みと主張
  （held_score 0.77前後のメタデータ入り、スナップショット2026-06-28）
- 注意: 誰でも使える配布物のため、LB中位帯にこのエージェントのクローンが複数いる
  可能性がある。敗因分析でブリジュラス系・フーディン/ノコッチ系に負けていたら
  デッキリスト完全一致を照合すること

## 結論

2体と我々の差は**定数の値ではなく、我々にはまるごと存在しない判断レイヤー**。
ステップ0校正実験の「エネ配分8定数は勝敗を左右しない」という実測結果と合わせて、
「700の壁の正体は定数チューニングではなく場合分け構造の欠落」説（ブレスト論点(b)）を
裏付ける証拠となる。

## 我々に無い4つの判断レイヤー（重要度順）

### ① クラッシュ安全ネット

- B: 方策本体を`_policy_agent()`に隔離し、外側の`agent()`ラッパーが
  (1) 例外時も必ず合法手を返す`_legal_fallback`、
  (2) 返却インデックスの範囲外・重複を矯正する`_normalize_ordered_indices`、
  (3) fallback発生率の診断カウンタ`_DIAG`、の三重の守りを持つ
- A: 1オプションの採点例外はそのオプションだけ-999999点にして続行。
  `choose_options`全体にもtry/exceptフォールバックあり
- 我々: 例外処理ゼロ。7/12修正の「TO_ACTIVEで毎回TypeError」バグ（e86e891）は
  このラッパーがあれば無傷だった。**全デッキに約15行で移植可能な最優先項目**

### ② 「今ターンのプラン」を先に立て、各選択肢はプランを参照する

- A: 採点前に「攻撃に到達するルート」を計算（直接攻撃／進化して特性でエネ加速して
  攻撃／撤退してベンチのアタッカーと交代、の3ルート）。ボスの指令・撤退・進化の
  採点は全てこのルート計算（`archaludon_ex_attack_route`/`planned_archaludon_attacks`）を参照
- B: 「今ターン相手のどれを倒せるか」を先に全員分計算（`estimate_hand_increase`で
  手札増加の上限を見積もり→ダメージ上限→特殊エネ剥がしに必要なハンマー枚数込みで
  KO可否判定）。その結果から「ボス指令が要るか」「特性ドローが要るか」「撤退用エネが
  要るか」を全部逆算してから各選択肢を採点する
- 我々: FieldStateは「盤面の枚数を数えた表」であり計画ではない。各選択肢を独立採点

### ③ 勝利条件（プライズ）の計算

- A: `prize_value`（ex=2, megaEx=3）を持ち、「この相手を倒せば残りプライズを
  取り切って勝ち」ならボスの指令に20000点（LETHAL判定）。バトル場KOだけで勝てる
  ならボスを温存
- B: 攻撃対象の優先順位が「1. 倒せば勝ち確定の相手 → 2. 倒せる中でプライズ最多 →
  3. とりあえずバトル場」。`prize_count`はLegacy Energy等による減算まで考慮
- 我々: プライズ枚数はリーリエの決心の判定にしか使っていない

### ④ 山札セーフティ（デッキアウト対策）

- B: 毎ターン `safe_draws = 山札残 − プライズ残 − 1` を計算し、**全ての**ドロー・
  サーチ札にそれぞれの実消費枚数でゲート（ポフィン2枚、フーディン進化時の特性
  ドロー3枚、テレパスエネ2枚、リッチエネ4枚…）。「今ターン勝てるなら無制限」の
  例外つき
- A: 「山札10枚以下で大量ドロー系サポート禁止」のハードルール＋Crustle対面専用の
  山札回復ルール
- 我々: lucario_agentには`DECK_SAFETY_THRESHOLD=15`があるが、**デッキアウト負けの
  実績があるgrimmsnarl_agentには未実装**

## その他の光る工夫

- A: マッチアップ検知（crustle/hop/starmie/lucario/alakazam/generic）＋**相手の
  ダメージ上限をマッチアップ別に推定**し、撤退・回復判断に使用。相手フーディンの
  ダメージは「相手の手札枚数×20＋盤面のドロー特性からの上振れ」まで見積もる。
  回復アイテムは「全部使っても相手の下限ダメージに届かないなら使わない」
- A: 相手の直前の攻撃をログ（LogType.TURN_END/ATTACK）から追跡（メガブレイブの
  「次のターン攻撃できない」状態を検知してボス温存に利用）
- A: 先攻/後攻の選択（IS_FIRST）で明示的に後攻を選ぶ。我々は無指定
- A: 攻め手がない時のボス指令「にげるコストが重くエネが付いていない相手を
  引きずり出して足止め」の時間稼ぎ採点式
- A: 弱点×2の`effective_damage`計算。我々は弱点非考慮
- B: 負債管理＝キチキギスex（きぜつで2枚取られ）は「特性ドローが勝ち筋に必要な時
  しかベンチに出さない」。テックカード（コダック・シェイミ）は対応する脅威が相手の
  盤面にいる時だけ出す
- B: ベンチ枠管理（残り1枠なら展開に-5000）
- B: 相手のACE SPEC使用をログから検知（ラッキーヘルメット/ジェネセクトの判断に使用）
- A: マイナス点＝「選ばなくていいなら選ばない」をminCount/maxCountと組み合わせて
  正しく処理。我々は常にmaxCount個を機械的に返すため「選ばない方が得な任意効果」を
  断れない
