# ドラパルトex ver8 実測ログ 5所感 調査結果（2026-07-25）

## 背景

ver7修正（`_attach_score()`エネルギー種別ガード／`_own_switch_target_score()`スボミー優先度引き下げ／`_cursed_bomb_score()`文鎮化ケース対応、コミット`ccc4f72`〜`0a172c8`、2026-07-24 mainマージ）をKaggleへ提出後、初めて取得した新規20戦バトルログ（`87789905`〜`87799545`、7/25保存）を解析した。

ユーザーからレーティング推移「784まで上昇→315まで急落→494で収束」の報告があった。バトルログのJSON自体にはKaggleレーティングは含まれないため直接の裏取りはできないが、20戦の勝敗は**12勝8敗（60%）**で、勝率としては壊滅的ではないものの、下記の通り「勝っても資源を無駄にしている」場面が構造的に多数見つかっており、レーティングの乱高下と整合的な材料が得られた。

**手法**：`src/etl/gold.py`の`GameStateTracker`でイベント列を1件ずつ再生し、本番の`main.py`のスコアリング関数を直接呼び出して検証。既知の罠（`steps[N]['action']`の1ステップずれ、`SWITCH`イベントのフィールド名の逆転、`observation.current`スナップショット不信用の原則）を踏まえ、5つの所感を独立した調査エージェントで並行検証した。

**対象デッキ構成の前提**：ドロメシヤ(Dreepy)→イダテヌキ(Drakloak)→ドラパルトex(Dragapult_ex)の進化ライン。ドラパルトexの実測maxHPは320、技「ファントムダイブ」の直撃ダメージは200（一撃では倒せない2ヒット制）。

## 所感a：無駄なエネルギー消費→にげる

### 判定：**バグ（確定）**

20戦中**12戦（60%）で16件**、エネルギーを装着した直後に一度も攻撃せず自分の意思で交代（にげる）し、装着したエネルギーがにげるコストとしてそのまま捨てられるケースが発生していた。16件中12件は同一ターン内で「装着→即にげる」が連続していた。

### 根本原因

1. **主因：`do_switch`条件（`main.py:965`）が広すぎる**
   ```python
   do_switch = (not can_main_attack and (bench_attacker or (active_id != Budew and field_counts[Budew] >= 1 and state.turn >= 2)))
   ```
   16件中15件で、装着した瞬間の盤面にすでにBudewが自分の場に存在しており、これが第2項（Budew節）を成立させ続けていた。「ベンチにアタッカー待機（`bench_attacker`）」よりも「Budewが場にいるだけでほぼ毎ターン交代を促す」設計の方が支配的な発火条件になっている。
2. **主因：RETREATのスコアリング（`main.py:1151-1155`）がエネルギー投資額を一切見ていない**
   `do_switch`が真なら一律score=10000、偽なら-1の二択。1ターン内で「装着」（先に選ばれる）→エネルギー枠を使い切った次の意思決定で「にげる」（`do_switch`が真のまま残っている）が続けて選ばれてしまう。
3. **副因（4/16件）：`_attach_score()`（`main.py:125-137`付近）が交代予定を考慮していない**
   `energy_count==0`かつアクティブかつ`bench_attacker`のとき+400点のボーナスがあり、まさに「ベンチに控えがいて交代が近い」状況で現アクティブへの装着を後押ししてしまう逆行ロジック。

## 所感b：ドロンチ在場中の無駄なベンチ手張り

### 判定：**バグ（確定）**

20戦中**8戦（40%）で9件**、アクティブの未攻撃可ドロンチ（Drakloak, 0エネルギー）を差し置いて、無関係なベンチのポケモンへ先にエネルギーが装着されていた（グレーゾーン3件、妥当な挙動5件は除く）。

### 根本原因

`_attach_score()`の`energy_count == 0`分岐（`main.py:125-137`付近）に、**アクティブ側にだけ種族ボーナスが欠落している非対称構造**がある：

```python
else:  # energy_count == 0
    if active:
        if bench_attacker:
            score += 400
        # ← アクティブ側には種族ボーナスが無い（bench_attacker=Falseなら常にscore=20000のまま）
    else:
        if pokemon.id == Dragapult_ex:
            score += 150
        elif pokemon.id == Dreepy:
            score += 100
        else:
            score += 50
        if bench_attacker:
            score -= 200
```

`bench_attacker`（控えに攻撃準備済みのドラパルトexがいるか）がFalseの場合、アクティブは常にscore=20000固定なのに対し、ベンチの0エネルギー個体はscore=20050〜20150となり、**種族に関係なくベンチが必ず勝つ**。実測9件のうち1件（試合`87799545`step114）は、ドラパルトラインですらないDuskull（ヨマワル）にまで流出しており、育成の主目的から見て明らかに不合理な結果になっていた。

これは2026-07-22に一度発見・修正されたenergy_count==1分岐の非対称バグ（ベンチ同士の比較）と同系統だが、**energy_count==0分岐のアクティブ vs ベンチ比較は未修正のまま残っていた**。

### 修正の方向性（提案、未実装）
`if active:`側にも`else`側と同じ種族ボーナス（Dragapult_ex +150 / Dreepy +100 / それ以外 +50）を追加すれば、アクティブとベンチが対等な条件で比較できる。

## 所感c：ミラー戦の敗因

### 判定：**バグ寄りの設計ギャップ＋サンプル不足の中間（n=4のため断定不可）**

20戦中ミラーマッチ（相手デッキにもDragapult_ex）は4戦（3敗1勝）。母数が小さく統計的な断定はできないが、3敗戦から2つの再現性あるコード上の弱点が見つかった。

- **87791487（敗北）**：自分が先にファントムダイブを撃てたが、確実キルできる控え（ドラクローク）へのメインダメージを優先し、相手ドラパルトex本体には副次ダメージ(60)のみ。相手はその後2発で自分のexを撃破。
- **87792309（敗北）**：相手がturn5に即ファントムダイブ、自分はturn9〜10まで進化が遅れ、決着はドラパルトex対決の前についていた（進化速度・引き運の問題）。
- **87792588（敗北）**：**手札にドラパルトexを最大3枚同時保持していながら、ベンチ5枠が他の駒で埋まり最後まで一度も進化できなかった。**
- **87793692（唯一の勝利）**：相手側のエネルギー事故（2本目が揃わず主力技を1回しか撃てなかった）に依存しており、自軍の判断が明確に優れていたとは言えない。

### コード上の具体的な弱点

1. **`main_option_proc`（`main.py:552-648`）**：このターンの即時プライズ価値のみを最大化する貪欲法で、「確実キルできる安い駒」と「相手ドラパルトex本体への部分ダメージ」を比較すると常に前者が勝つ。ミラー戦で相手も同じ2ヒット制の的である以上、「1発目を相手の主力に入れておく」戦略的価値が未反映（87791487の敗因の一部）。
2. **`hand_score()`（`main.py:773-935`）の副次アタッカー系カード（Yveltal/Moltres/Munkidori/Fezandipiti_ex/Duskull系統）にベンチ枠の予約ロジックが無い**：これが87792588の敗因そのもの。序盤の劣勢で副次アタッカーを次々場に出すが、本命の進化ラインのためのベンチ枠を確保しないため、ベンチが埋まって主力を一度も出せなくなる。**ミラー戦特有ではなく一般的な設計ギャップだが、相手のファントムダイブ散らしダメージで低HPの序盤個体が狩られやすいミラー戦で顕在化しやすい構造。**

## 所感d：動けないターンが多い理由

### 判定：**限定的に確認（少数派）、主因は既知のno_drawゲート**

「PLAY/ATTACH/EVOLVE/ABILITYのいずれも選ばれなかったターン」は161ターン中**15件（9.3%）、4戦（87793122, 87793692, 87795296, 87796883）に集中**。20戦中16戦では一度も発生しておらず、「動けないターンが多い」という所感ほど支配的な現象ではなかった。手札に本当に選択肢が無い「純粋な手札事故」は0件。

### 内訳

| 分類 | 件数 |
|---|---|
| no_draw型（既知の未修正課題） | 10 |
| 手順・判断ロジック型 | 5 |

- **no_draw型（10/15件）**：`main.py:964`の`no_draw = (my_state.deckCount <= 8)`が`main.py:1134-1135`で全ABILITY選択肢を一律ブロック。**加えてPLAY側の複数TrainerCardPolicy（Ultra Ball/Poké Pad/Crispin/Buddy-Buddy Poffin）も同じ`no_draw`で一律ブロックされていることを確認**（タスク定義はABILITY限定だったが、実態としてはPLAY側にも及んでいた）。既存バックログ課題（2026-07-23発見・未修正）の実害を今回のログで初めて具体的に確認できた形。
- **手順・判断ロジック型（5/15件）**：うち1試合（87793692、2ターン）で新規の相互作用バグを発見。`_attach_score()`のDusknoir/Dusclops分岐（`main.py:98-100`）が**エネルギー種別を問わずscore=500**を返すため、「行き場のないエネルギー」がヨノワール/サマヨールに装着されてしまい、`_cursed_bomb_score()`の`energy_count==0`前提（`main.py:251`）を永久に崩す。他にベンチの2エネルギー付きドラパルトexがいてもカースドボムが発動不能になっていた。残り1件（87796883）は`no_more_dex`によるRare Candyの正当なブロックで、バグではない。

## 所感e：サマヨールが自爆（カースドボム発動）しない理由

### 判定：**バグではなく意図的な設計（2026-07-24のver7修正そのもの）**

ABILITY選択肢にDusclops/Dusknoirが出現したのは20戦中15戦・57機会（ターン単位）。実際に発動したのは**7件**、未発動は**50件**。

未発動50件の内訳：
- no_drawゲートが唯一の原因だったケース：**0件**
- `_cursed_bomb_score()`自体が負スコアだったケース：**50件**（内訳：他に攻撃可能な駒がいない34件／既にエネルギーが付いている16件）

**no_drawゲートは今回のログでは未発動の原因になっていなかった。** 主因は`_cursed_bomb_score()`（`main.py:235-253`）自体の発動条件で、これは2026-07-24のver7修正で意図的に導入されたものである：

```python
if energy_count == 0 and has_other_attacker:
    return 20000
return -1
```

docstring（main.py:243-248）に明記の通り「本命アタッカーを犠牲にするリスクを避けるため、他に攻撃札が無い場合は発動しない」という設計判断。34件（68%）はまさにこの「他に攻撃可能な駒がいない」ケースで、サマヨール/ヨノワール自身が唯一の攻撃要員になっている典型的な中盤〜終盤の展開だった。

**この34件は所感eの「自爆しない」という体感の直接的な原因であり、かつ現在のコードは意図的にそう作られている。** 「唯一の攻撃要員でも自爆を許すべきか」はリスク許容度のトレードオフであり、技術的な正誤ではなくユーザー判断が必要な論点。

残り16件（エネルギーが付いていて発動不能）は、**所感dで発見した相互作用バグ（`_attach_score()`のDusknoir/Dusclops分岐がエネルギー種別を問わず装着を許す）と同一の原因**である可能性が高く、独立した2つの調査が同じ根を指し示した。
