# ルカリオexデッキ ver22（Maximum Belt版）提出後20戦の実測検証

- 日付: 2026-07-28
- 対象ログ（20戦、いずれも`Kagura_UT`視点）:
  `88163612, 88164161, 88164709, 88165229, 88165756, 88166297, 88166332, 88166826, 88167356, 88167892, 88168475, 88169005, 88169543, 88170079, 88170603, 88171158, 88171670, 88172267, 88172790, 88173336`
- ver22とは: 2026-07-26にACE SPEC枠を **Hero's Cape(ID 1159) → Maximum Belt(ID 1158)** へ差し替えた版
  （実装サマリー: `docs/implementations/20260726-lucario-maximum-belt-dragapult-counter.md`）
- スコア推移（ユーザー報告）: **600 → 1001 → 591.3**
- 目的: 2026-07-26のMaximum Belt導入時にバックログ化した3つの未確認事項を実測で検証する
  1. Dragapult ex系トゥールボックスへの勝率改善（従来3戦3敗=0%）
  2. ふうせん(Air Balloon)とMaximum Beltのどうぐ枠競合の有無
  3. Hero's Cape喪失によるMega Lucario exのHP低下(440→340)の実害
- 手法: 3体の独立したサブエージェントが並行して検証。いずれも`src/etl/gold.py`の`GameStateTracker`による
  イベント再生ベース（スナップショット判定は過去に信頼できないと判明済みのため不使用）

## 結論（先に要点）

- **勝率は8勝12敗(40.0%)。ver20(44.4%)・ver21(45.0%)から改善していない**（差は1試合分で有意ではない）。
  この数値は担当A・担当Cが独立に集計して一致しており信頼できる
- **Dragapult ex戦は20戦中1戦しか発生せず(0勝1敗、n=1)、Maximum Belt導入の効果は検証できなかった**。
  しかもその1戦ではBeltを最後まで引けず、Mega Braveもエネルギー不足で1回も撃てていない。
  「設計が失敗した」のではなく「試す土俵に上がれなかった」というのが正確
- **Maximum Beltの機構自体は正しく動作していることを実証**。別試合で`Mega Brave 270 + Belt 50 = 320`
  ちょうどの実測が2件、Premium Power Pro込みで350が1件。非アタッカーへの浪費0件（7/26の温存修正は実測で機能）
- **Hero's Cape喪失の実害はほぼ確認されず**。単発341〜440のダメージを受けた場面は0件（実測最大330）
- **最重要の発見：真の失点源はDragapultではなくAlakazam（フーディン）軸**。相手20戦中8戦(40%)を占め、
  そこで2勝6敗(25%)。技「Powerful Hand」（相手の手札1枚につきダメカン2個）で実測320〜480ダメージを受けており、
  **HP上限やどうぐの差し替えでは原理的に対処できない**。この弱点は2026-07-18・2026-07-25に続き**3回目の再現**

## 0. スコア推移について

ユーザー報告では **600 → 1001 → 591.3**。1001は本プロジェクトのこれまでのピーク（ドラパルトex ver4の835）を
上回る過去最高値だが、そこから591.3まで急落している。

2026-07-26の検証（`20260726-lucario-ver20-ver21-score-noise-and-opponent-check.md`）で
**「同一ロジックを再提出しても収束スコアが100点以上動く」＝レーティングシステム由来のノイズ**であることを
既に確認済みだが、今回の変動幅（約410点）はそれを大きく上回る。今回も勝率40%は過去バッチ(44〜45%)と
ほぼ同水準であり、**スコアの絶対値でロジックの良し悪しを判断するのは引き続き危険**という結論を補強している。

## 2. Dragapult ex戦の検証（該当1戦のみ、88169005、敗北）

該当試合は`88169005`の1戦のみ（他19戦の相手デッキにcardId 121は0枚）。me_idx=1、`rewards=[1,-1]`で敗北。

### Maximum Belt：装着ゼロ。原因は「引けなかった」

自分視点ストリーム（`build_event_timeline(data, player_index=1)`）でcardId 1158を全走査した結果、
イベントは以下の2件のみ:

- `step=111 MOVE_CARD fromArea=1(DECK) → toArea=12(LOOKING)`
- `step=112 MOVE_CARD fromArea=12(LOOKING) → toArea=1(DECK)`

これは`step=111`でプレイしたPokégear 3.0[1122]（山札上7枚を見てサポートを1枚取る）による覗き見。
Maximum Beltはポケモンのどうぐなので**規則上取得できず山札に戻された**。エージェントの選択ミスではない。
ATTACH/DRAWイベントは0件で、試合終了時点でもトラッシュ・場・ベンチに1158は存在しない。

### Mega Brave（attackId 983）：一度も使用せず。原因はエネルギー不足

Mega Lucario ex[678] serial=67の攻撃は2回、**両方ともattackId=982（はどうづき／130ダメージ）**。

- `step=146` → Dragapult ex serial=11に`HP_CHANGE value=-130`
- `step=167` → Dragapult ex serial=11に`HP_CHANGE value=-160`（130 + Premium Power Pro[1141]の+30、`step=166`でプレイ確認）

`GameStateTracker`でエネルギーを再生した結果、**両攻撃時点でserial=67のエネルギーは1個のみ**
（Basic {F} Energy[6] 1枚）。Mega Braveのコストは闘闘＝2個なので**そもそも選択肢に出ていない**。

serial=67は`step=140`にベンチのRiolu serial=63（エネルギー0）から進化した個体で、`step=145`に1枚付けただけ。
**はどうづきの効果はトラッシュの闘エネルギーをベンチにしか付けられない**ため
（実際step=148/149/169でベンチのRiolu serial=65に流れている）、バトル場のMega Lucario自身は
2個目を得られないまま倒された。

→ **構造的な問題として記録**: Mega Lucario exがバトル場で2エネ目を確保する手段が細い。
Dragapult戦の敗因の一部であり、Belt導入とは独立した課題。

### 「320を1発」は0回。ただし機構自体は他試合で実証済み

この試合のDragapult ex serial=11（HP320）は`100 + 130 + 160 = 390`を**3回に分けて**削られ`step=171`にKO。
一撃320は出ていない。一方、他試合には320の実測がある:

| 試合ID | step | 内容 |
|---|---|---|
| 88164161 | 147 | Mega Brave → 相手Mega Lucario exに`value=-320`（270+50。Belt装着は`step=141` ATTACH cardId=1158 → serialTarget=68） |
| 88165756 | 112 | Mega Brave → Marnie's Grimmsnarl exに`value=-320`（Belt装着は`step=111`） |
| 88165229 | 91 | Mega Brave → `value=-350`（270+50+Premium Power Pro 30） |

→ **Maximum Beltの+50は正しく乗る**。問題は「ドラパルト戦で引けるか」だけ。

### 敗因の切り分け：手札事故ではなく既知の構造的弱点そのもの

Phantom Dive（attackId 154）は4回撃たれた（自分視点step=109/137/165、相手視点ストリームstep=178）。
決定打は`step=137`の1発:

- `HP_CHANGE Solrock[676] serial=70 value=-200`（バトル場、KO）
- 同時にダメカン6個 → `Riolu[677] serial=64`、`Riolu serial=63`、`Cornerstone Mask Ogerpon ex[117] serial=75`に分配
- 結果、`step=137`で**Solrock serial=70 / Riolu serial=64 / Ogerpon ex serial=75の3体が同時にACTIVE|BENCH→DISCARD**
  （Ogerpon exは`step=109`の1発目で既に-200を受けており、HP210に対しベンチでのダメカン1個で落ちた）
- ex1体を含む3体同時KO＝一気に4枚サイドを取られ、ここで実質的に決着

手札事故の兆候（マリガン連発・ドロー詰まり）は見当たらず、**アクティブ200＋ベンチ60の同時分配で
「削りかけのベンチ」がまとめて刈られる非対称性**という、2026-07-26に特定済みの弱点が再現したと判断できる。

### 懸念A（どうぐ枠の競合）→ ハードな競合は0件

- 「装着済みの対象に新規ATTACHが発生した」パターン（ツール上書き）を全イベント走査 → **0件**
- ゲームエンジンが装着を拒否した／強制的に外して付け替えた形跡
  （`MOVE_CARD fromArea=TOOL → discard`の直後に同一ターゲットへ再ATTACH）も **0件**
- discard→再装着ではなく、discard(=KO)後は当該ポケモン自体が場からいなくなっている

**ソフトな競合の実例1件**: `88168475` turn3、進化直後で無装備のMega Lucario ex(serial8)に対し、
turn1から手札にあったMax Beltではなく**Air Balloonが優先装着された**（step=27）。Max Beltはこの試合を通じて
一度も装着されず。ただし実害検証の結果、相手の唯一のexだったFezandipiti ex(HP210)が場に出たのはturn9・
アクティブ化はturn11で、turn11の攻撃は+50無しでも260ダメージでHP210を超過し即KOできていた。
→ **このケースでは実害なし**。ただし優先度次第でMax Beltが割を食う構造は実在する。

### 懸念B（非アタッカーへの浪費）→ 0件。7/26の温存修正は機能している

Max Beltが実装着された6戦の装着先は**Riolu 3件・Mega Lucario ex 3件のみ**。
Lunatone/Solrock等の非アタッカーへの誤装着は**0件**。

カード原文（`data/competition/EN_Card_Data.csv`）で確認: Hero's Cape(1159)「+100 HP」、

Riolu（素HP80）のKOは8件あるが、ACE SPECは1枚しか積めずMega Lucario ex優先運用のため反実仮想の対象外。

### 判定内訳

- **直接的ケース（単発341〜440を1発で受けてKO）: 0件**。相手の単発技ダメージの実測最大は330
  （`88170079` step=129、ミラーのMega Lucario ex）で、**341〜440の帯に入る攻撃は1回も観測されなかった**
- **可能性どまり（累積型・Cape装着ならその一撃は耐えた）: 5件**（うち3件が負け試合）。
  ただし相手の次ターンの追撃で結局倒された可能性は否定できず**断定不可**
- **無関係（Capeがあっても倒された）: 2件**（いずれもAlakazamの手札枚数比例ダメカン）

**重要な前提**: この5件はいずれも実際にはACE SPEC未装着（うち2件はMaximum Belt装着済み）。
「Capeなら耐えた」は**Capeがその個体に貼られていた場合**の話であり、ver21で実際にそう貼られていたかは
ver22のログからは確認できない。

### 高火力（一撃300以上）の相手との戦績

- 技ダメージ300以上を受けた試合: **2戦0勝2敗**（`88170079`=330 / `88172790`=300、どちらもミラー）
- ダメカン配置300以上を受けた試合: **4戦0勝4敗**（`88168475`=320 / `88170603`=480 / `88171158`=420 /
  `88172267`=340、すべてAlakazam「Powerful Hand」系）
- 合算すると**「一撃300超」を出す相手には6戦0勝6敗**

### 総合所見

**「Hero's Capeを戻せば勝てた」と言える証拠はこの20戦には無い。** 341〜440の技ダメージを出す相手が
環境に存在しなかった（実測最大330）ため、+100が「1発耐える」形で効く場面は元々ほぼ無かった。
一方で累積型5件は影響圏内にあり、無視できる差でもない。差し替えの是非としては**中立**。

## 5. 最重要の発見：Alakazam（フーディン）軸への構造的な弱さ

3体のエージェントが別々の切り口から**同じ結論に到達した**。

- 相手20戦中**8戦(40%)がAlakazam軸**で、そこで**2勝6敗(25%)**
- 技「Powerful Hand」（Alakazam[743]）。実測で**320・340・400・420・480ダメージ**を観測

> **【2026-07-28訂正】** 本節の初版では「**相手（＝我々）の**手札1枚につきダメカン2個」と記述していたが、
> **これは誤り**。カード原文はEN "Place 2 damage counters on your opponent's Active Pokémon
> **for each card in your hand**" / JP「**自分の手札の枚数**×2個ぶんのダメカンを、相手のバトルポケモンにのせる」で、
> **参照されるのは撃つ側（Alakazam側）の手札**である。ver23の実測6回すべてで
> `ダメージ = Alakazam側の手札枚数 × 20` が完全一致し、我々の手札とは無相関であることを確認済み。
> **対策の方向は「自分の手札を減らす」ではなく「相手の手札を減らす／ドローさせない」（Judge等）。**
> 詳細は `docs/analyses/20260728-lucario-ver23-noise-verification.md` 第4節を参照。
- ダメカンの直接配置なので**HP上限を100増やしても届かず、Belt・Capeどちらでも解決しない**
- 全20戦の負け12戦のうち**4戦がこのタイプ**

### この弱点は3回目の再現

| 時期 | 戦績 | 対応状況 |
|---|---|---|
| 2026-07-18 | 深掘り分析実施（`docs/analyses/20260718-lucario-alakazam-deep-dive.md`） | 分析のみ |
| 2026-07-25 | 6戦1勝5敗(17%) | 「優先度引き上げ要否をユーザーと相談」が申し送られたまま**未対応** |
| 2026-07-28（今回） | **8戦2勝6敗(25%)** | 本ドキュメント |

**環境の4割を占める相手に負け越し続けている**ことが、勝率が44〜45%から40%の壁を越えられない
構造的な理由である可能性が高い。コンペ締切（2026-08-17）まで残り約3週間を踏まえると、
Dragapult対策よりこちらの優先度が高いと考えられる。

## 6. 手法・根拠にしたJSONフィールド

- 勝敗: `data["rewards"]`（最大値のindex）× `info.Agents[i].Name`
- デッキ60枚: `steps[0][0]["visualize"][0]["action"][player_index]`（`extract_deck_list`と同一ロジック）
- イベント: `steps[i][player_index]["observation"]["logs"]`を`build_event_timeline`で再生。
  type=4 DRAW / 6 MOVE_CARD / 8 SWITCH / 11 ATTACH / 12 EVOLVE / 15 ATTACK / 16 HP_CHANGE
- エネルギー数: `GameStateTracker.energy_count`（スナップショット不使用）
- ダメージ種別の判別: `HP_CHANGE`の`putDamageCounter`（ダメカン配置か技ダメージか）
- カード原文: `data/competition/EN_Card_Data.csv` / `JP_Card_Data.csv`
- カードID定数: `src/lucario_agent/constants.py`

### 検証の裏取り

## 7. 【重要】分析ツール側で判明した罠（次回以降の必読事項）

**`build_event_timeline(data, player_index=0)`を決め打ちで呼んではいけない。**

- 自分のindexは試合ごとに0/1で揺れる（今回20戦中 index0=9戦 / index1=11戦）
- `player_index=0`固定だと、自分がindex=1の試合で**自分の非公開イベント（DRAW・山札サーチ）を取りこぼす**。
  担当Aはこの罠を踏みかけた（p0ストリームでは`88169005`のMaximum Beltイベントが0件に見えた）
- さらに、自分の初期アクティブ配置が`MOVE_CARD_REVERSE`（伏せ札）としてしか見えず、
  `GameStateTracker._apply_switch`のassertが落ちる（`88163612.json`で実測）
- **`src/etl/gold.py`の`extract_attack_events`等は`player_index=0`決め打ち**になっているため、
  同種の分析をする際は必ず`find_player_index`で自分のindexを取得してから渡すこと

**同じイベントでも観測ストリームによってstep番号がずれる**（`88169005`の最終攻撃は自分視点で追えず、
相手視点ストリームでstep=178/184）。本ドキュメントのstep番号は断りがない限り自分視点。

## 8. 確認できなかったこと・注意点

- **Dragapult ex戦はn=1**。「ver22はDragapultに強くなった／弱いままだ」と結論することは**できない**。
  判断にはサンプルの追加収集が必要
- `88167892`はMax Belt装着直後(turn11)でログが実質終了（`total_steps=109`、RESULT未記録）。
  装着後に+50込みの攻撃が実際に発動したかは**未確認**
- `HP_CHANGE`の値は弱点/抵抗力/Max Belt+50が合算済みで個別分離不可。
  「+50が乗った」の判定は状況証拠（相手アクティブがex・ダメージ量の妥当性）に留まる
- `88169005`でMaximum Beltがサイド落ちだったのか山札に残ったのかは、自分視点スナップショットの`prize`が
  伏せ表示のため**特定できなかった**。確実に言えるのは「手札に来ず、装着されなかった」ことのみ
- 懸念A（枠競合）の「選ばれなかった」判定は、スコア計算ロジックを読んだ上ではなくログ上の行動結果からの推測
- ver21（Hero's Cape版）の実ログとの直接比較はしていないため、Capeが実際にMega Lucario exに
  貼られる頻度は不明
- Riolu 3件でスナップショット値と再生値が10〜30ずれた（`88169005` step=137、`88169543` step=113等）。
  スナップショット側のラグと見られるが原因は特定していない。Mega Lucario ex側にはズレ無し
- アーキタイプ別戦績はAlakazam軸(n=8)以外すべて**n=1〜4で断定不可**
