# レビューサマリ：グリムスナールexデッキ「控えポケモン誤出場」バグ調査

**調査日：** 2026-07-03
**きっかけ：** ユーザー報告「マリィのオーロンゲexデッキ、スコア431〜624の乱高下。控えに出さないといけないポケモンをバトルフィールドに出してしまっている。勝ち方も美しくない」
**対象バトルログ：** `83347688` / `83433347` / `83438721` / `83444801` / `83474441` / `83502424`（ID先頭3桁が833〜835、いずれも自分＝Kagura_UTの対戦）

---

## 調査方法

1. 上記6件を `scripts/etl_battle_log.py` でETL（bronze/silver化）
2. `data/JP_Card_Data.csv` の`カード ID`列でカード名解決
3. 各ログの生JSON（`steps`配列）を直接パースし、`select.context`が`SWITCH`(3)/`TO_ACTIVE`(4)の場面で
   - 選択肢一覧（ベンチのポケモンとHP）
   - 実際にエージェントが選んだインデックス（`action`は該当observationの**次のstep**に記録される点に注意）
   を突き合わせて実際の選出結果を追跡

---

## 発見①（今回の直接原因）：SWITCH/TO_ACTIVEスコアリングの同点デフォルト選択バグ

**該当コード：** `src/grimmsnarl_agent/main.py:236-241`

```python
def _score_own_switch_target(card: "Pokemon") -> int:
    score = len(card.energies) * 2
    if card.id == Grimmsnarl_ex:
        score += 100
    return score
```

グリムスナールexが場にいれば`+100`で正しく最優先される（`83438721` step72では実際に320HP満タンのグリムスナールexが正しく選出されていた＝ロジックは機能する場面もある）。

しかし**グリムスナールex不在の場面**では、エネルギー0枚同士は全員スコア0の同点になる。Pythonの`sorted(..., reverse=True)`は安定ソートのため、同点時は**ベンチ0番目**が機械的に選ばれる。この結果、HPや役割を一切考慮せずに「たまたまベンチ0番目にいたポケモン」が前に出されてしまう。

**具体的な誤選出の証拠：**

| ログ | step | ベンチ状況 | 選ばれたもの | 選ばれるべきだったもの |
|---|---|---|---|---|
| 83347688 | 91 | スボミー(30HP) / イベルタル(110HP) / シェイミ(80HP) / ベロバー(70HP) | **スボミー(30HP)** | イベルタル(110HP・実戦可能) |
| 83438721 | 125 | コダック(40HP・被弾済) / ベロバー(70HP) / シャリタツ(70HP) / イベルタル(110HP) / ベロバー(70HP) | **コダック(40HP)** | イベルタル(110HP) |

いずれも「特性専用・本来ベンチに置いておくべきポケモン」が低HPのまま前に出され、早期きぜつ→被プライズ増加につながっていた。これが報告されたスコアの乱高下（431〜624）と「勝ち方が美しくない」の直接原因と特定。

## 発見②（副次的）：マシマシラ（Munkidori）の特性が実質機能していない

**該当コード：** `src/grimmsnarl_agent/main.py:217-224`

```python
def _score_attach(pokemon, area, card_id, fs) -> int:
    energy_count = len(pokemon.energies)
    if card_id == Basic_D_Energy:
        if pokemon.id == Grimmsnarl_ex:
            return 9000 - energy_count * 1000
        return -1  # グリムスナールex以外には基本エネルギーを絶対に貼らない
    return 3000
```

マシマシラの特性「アドレナブレイン」（ダメカン移動）は自身に【悪】エネルギーが付いている場合のみ発動する。ユキメノコ／シェイミ／スボミー／コダック／シャリタツの特性は無条件発動だが、マシマシラだけはエネルギー要求がある。しかし現在の設計はグリムスナールex以外に基本エネルギーを一切貼らないため、**3枚採用しているにもかかわらずマシマシラの特性は永久に発動しない**状態だった。

## 発見③（デッキ構成レベルの論点）

特性専用・バトル場を想定しないポケモン（ユキメノコ104／スボミー235／シェイミ343／シャリタツ122／コダック858）の座組が厚く、これが発見①のバグの影響範囲を広げている一因ではないか、という仮説をユーザーと共有。上位勢実績のあるキチキギスex(140・悪タイプ・210HP)採用や座組整理は、スコアリング修正とは別スコープの構成見直しとして扱う。

---

## 今後の対応（2段階）

- **フェーズA（対応中）：** スコアリングロジック修正
  1. `_score_own_switch_target`にHP考慮スコアを追加し、特性専用ポケモンを明確に減点
  2. `_score_attach`を修正し、余剰の基本エネルギーはマシマシラにも貼れるようにする
  3. TDDで失敗するテストを先に書いてから実装、既存テスト回帰なしを確認
- **フェーズB（後続）：** デッキ構成見直し（キチキギスex採用検討、特性専用ポケモンの枚数整理）。フェーズA完了後、ユーザーがセッションをクリアしてから着手。
