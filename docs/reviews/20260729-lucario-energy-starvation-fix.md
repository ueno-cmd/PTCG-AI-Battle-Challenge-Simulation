## ブランチ全体レビュー（Opus）で発見された計画の欠陥

**これが本作業で最も重要な指摘。**

### 指摘内容

Task 2 で追加した救済ボーナス +500 は、同じ関数内の
**Rock_Fighting_Energy のアクティブ優先 +500 と排他ではなく加算される**。
計画書が書いた「素の `energy_score`（7900〜8101）とだけ競合する」という前提は誤りで、
ATTACH の実際の最大値は **9130** に達していた。

これは 2026-07-28 に自ら立てた不変条件 **「9000〜10000の間に他のスコアは存在しない」**
（`main.py` の EVOLVE 分岐コメントで明示的に宣言。EVOLVE を Judge との同点事故から守るためのもの）を破っていた。
EVOLVE は `9100 + エネ数` なので、ATTACH が EVOLVE を追い越す順序逆転が発生していた。

**同点（完全一致）自体は総当たり検証で0件、実害もゼロ**（MAIN は1ターンに複数回行動できるため
装着→進化で両立する）。問題は**コードに「破られていない」と書いてあるまま帯域が侵食されている**ことで、
次にこの帯域へ加点した人が7/28と同じ事故を起こす温床になっていた。

**これは実装ではなく計画（AIが作成）の欠陥である。**

### 対応

**ユーザー判断により救済ボーナスを +500 → +300 に変更。** 最大値が 8930 となり 9000 未満に収まった。
副次的に、救済が ABILITY のルナサイクル（8500）を追い越して「引いてから付ける」順序が
「付けてから引く」に反転していた退行も解消された。

加算関係は回帰テスト
`test_rock_fighting_energy_rescue_stacks_with_active_priority_and_stays_below_evolve` で固定した。
